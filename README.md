# PDE Lab: сеточный метод и Монте-Карло

Рабочая исследовательская программа для **Δu = f в единичном квадрате, u = g на границе**. Четыре метода, сравнение с точным решением там, где оно известно, графики, анимации и русскоязычный интерактивный интерфейс. По умолчанию вычисляется **одна точка в центре**.

Это первый стационарный этап темы: постоянный коэффициент, равномерная квадратная сетка, условия Дирихле. Нестационарное уравнение теплопроводности, нелинейная теплопроводность и уравнение Бюргерса пока не реализованы. Итерации базового решателя не являются физическим временем.

## Самый быстрый просмотр

Откройте `examples/index.html` обычным браузером. Готовые расчёты для точки, участка и поля не требуют Python или интернета. В каждом примере есть `interactive.html`, PNG, CSV и массивы NPZ. В примерах точки и поля также есть GIF. HTML можно отправить преподавателю одним файлом.

## Четыре метода

| Метод | Что реализовано | Что сравнивать |
|---|---|---|
| ЛОМ | Факторизованная поправка по невязке; последовательные прогонки | Время до заданной невязки |
| Монте-Карло | Независимые блуждания от каждой запрошенной точки до границы | RMSE, относительная ошибка, число шагов, время |
| MC, хвосты | Из каждого пути берётся хвост после первого посещения другой целевой точки | Точность при том же бюджете путей и время при сопоставимой ошибке |
| MC, слои | Расчёт от границы внутрь; пути останавливаются на завершённых слоях | Сокращение длины пути с учётом подготовки и переноса неопределённости |

Название «ЛОМ» в интерфейсе обозначает выбранный для стационарной задачи решатель с расщеплением по направлениям. Это **конкретная факторизованная итерационная схема**, а не заявление о реализации любой схемы ЛОМ из литературы. Согласуйте с преподавателем именно эту формулу, если требуется определённая учебная схема.

### Общая дискретизация и знак источника

Имеется n интервалов по каждой оси, h = 1/n, (n+1)² узлов. Массивы индексируются `[y, x]`.

```text
Lh u = (u[x+h,y] + u[x-h,y] + u[x,y+h] + u[x,y-h] - 4u[x,y]) / h² = f
u[x,y] = среднее четырёх соседей - h² f[x,y] / 4
```

Все четыре метода решают одну разностную задачу. **Основной эталон в таблицах и графиках — точное аналитическое решение**, если оно известно для выбранных точек. Это полином, синус и линейное поле; для постоянных температур сторон при f=0 также известен точный ответ в центре — среднее четырёх сторон. При стандартных условиях он равен 25.

Если точное решение для всего выбранного набора точек в программе не задано, используется прямое сеточное решение `scipy.sparse.linalg.spsolve`. Тип эталона всегда подписан. Не смешиваем разные эталоны внутри одной RMSE: например, для участка вокруг центра в примере с нагретым краем используется сеточный эталон для всех девяти точек.

В единой таблице показаны значение (для одной точки), время, RMSE, относительная ошибка, новые пути, шаги и итерации. Относительная ошибка `relative_error_pct` = 100 × ‖u − эталон‖₂ / ‖эталон‖₂ по запрошенным точкам. Для одной точки это 100 × |u − эталон| / |эталон|. Если эталон равен нулю во всех выбранных точках, процент не определён (пустое значение в CSV/JSON, прочерк в HTML); используйте RMSE. Это отношение норм, а не среднее поточечных процентов: нулевые значения в части узлов не вызывают деления на ноль.

При сравнении с аналитическим решением ошибки включают пространственную погрешность сетки. Поэтому у ЛОМ на синусе ошибка останется даже при очень малой невязке. `rmse_grid` сохранён в сырых данных для проверки решателя относительно прямого решения той же сеточной системы; это не оценка погрешности сетки. Отдельной таблицы диагностики нет. Максимальная ошибка и SE исключены из таблиц; неопределённость MC по-прежнему рассчитывается для поясняющих графиков.

Прямой решатель используется для независимой диагностики и при наличии точного решения. Его время записывается отдельно и не считается временем какого-либо исследуемого метода. Когда точный ответ известен только в центре, полная фоновая поверхность остаётся сеточной и подписана отдельно; ошибки в центре считаются к точному ответу.

### Базовый решатель

Начальное внутреннее поле равно нулю, граничные значения заданы точно. На каждом шаге:

```text
r = Lh u - f
τ = h / (2π)
(I - τ Lx) v = τ r
(I - τ Ly) δ = v
u ← u + δ
```

Поправка на границе равна нулю. Каждая из двух систем распадается на одномерные трёхдиагональные системы, решаемые прогонкой. Линии внутри прохода и два прохода выполняются последовательно. Обновление эквивалентно `(I-τLy)(I-τLx)δ = τr`; неподвижная точка удовлетворяет исходной системе `Lh u=f`. Здесь нет дополнительного стационарного смещения от расщепления. Критерий остановки: `‖b − A u‖∞ / ‖b‖∞ ≤ tol`; недостигнутая точность не выдаётся за успешный расчёт.

Здесь `A` — матрица для внутренних неизвестных (`−Lh` с нулевой границей), а `b` содержит `−f` и известные граничные значения, перенесённые в правую часть с коэффициентом `1/h²`. Поэтому нормировка работает и при `f = 0`. При нашем нулевом начальном внутреннем поле `‖b‖∞` совпадает с начальной абсолютной невязкой. Если `b = 0`, начальное поле сразу является решением и итерации не нужны. Деления на ноль и искусственного абсолютного порога нет.

`tol` — безразмерная доля между 0 и 1: например, `1e-2` означает 1%, а значение по умолчанию `1e-7` означает 0,00001%. Это относительная невязка уравнения, не относительная ошибка решения в основной таблице. В серии используются допуски `1e-2`, `1e-4`, `1e-6`, `1e-8`. Увеличение `max_iter` не отменяет проверку сходимости. Монте-Карло по-прежнему останавливается по фиксированному числу путей.

Это не оптимизированный промышленный решатель: τ фиксирован, число итераций зависит от сетки и допуска. Реализация проверена сравнением с прямым решением той же сеточной системы.

Прогонка в `_solve_line` записана через коэффициенты α и β, как в
[описании метода](https://ru.wikipedia.org/wiki/Метод_прогонки):

$$
A_i v_{i-1}+B_i v_i+C_i v_{i+1}=F_i,
\qquad v_i=\alpha_{i+1}v_{i+1}+\beta_{i+1}.
$$

Прямой ход:

$$
\alpha_{i+1}=\frac{-C_i}{A_i\alpha_i+B_i},
\qquad
\beta_{i+1}=\frac{F_i-A_i\beta_i}{A_i\alpha_i+B_i}.
$$

Для наших проходов `a = c = -q`, `b = 1 + 2*q`, где `q = τ/h²`.
`rhs_value` соответствует `F_i`: на проходе по x это `τ * residual`,
на проходе по y — результат первого прохода.

В коде внутренние узлы одной линии нумеруются с 0 до `size - 1`.
Поправка на обоих концах линии равна нулю: начинаем с `alpha[0] = beta[0] = 0`,
а обратный ход — с `v[size - 1] = beta[size]`.
Далее восстанавливаем значения по `v[i] = alpha[i + 1] * v[i + 1] + beta[i + 1]`.
Эти нулевые условия относятся к поправке; граничные значения исходного поля
уже учтены при вычислении невязки.

### Обычный Монте-Карло

Из каждого внутреннего узла частица равновероятно переходит к одному из четырёх соседей. Один путь даёт:

```text
Y = g(первое попадание на границу) - (h²/4) × сумма f по внутренним посещениям
û = среднее Y по независимым путям
SE = выборочное стандартное отклонение Y / √N
```

Повторные посещения входят в сумму источника. Для Δu=f знак перед суммой отрицательный. Блуждания оценивают **сеточное** решение: увеличение N не убирает пространственную погрешность сетки. Защитный предел длины пути вызывает ошибку, а не обрезает путь и не возвращает смещённый ответ.

### Улучшение 1: хвосты путей

Если путь из A впервые посетил целевой узел B, оставшаяся часть пути даёт одно наблюдение для B. Из полного вклада вычитается накопленный источник до первого посещения B. Каждый исходный путь учитывается для данного узла не более одного раза. Все повторные посещения не считаются независимыми наблюдениями.

Реализация генерирует N новых путей из **каждой** целевой точки, как обычный MC, в том же порядке и с тем же seed. Это фиксированный план, а не остановка после случайного достижения квоты. Длина сгенерированных путей одинакова с обычным MC, но другие точки могут получить дополнительные наблюдения. Учёт хвостов сам по себе требует времени; улучшение проверяется по кривой «время - ошибка» при разных N.

Для **одной точки** дополнительных наблюдений нет: оценка точно совпадает с обычным MC. Оценки разных точек коррелированы, потому что могут использовать один исходный путь; их нельзя считать независимыми при расчёте неопределённости интеграла по полю.

### Улучшение 2: слои от границы

Сначала известна настоящая граница. Затем вычисляются все узлы первого внутреннего слоя, второго и так далее до самой глубокой цели. Во время расчёта очередного слоя набор известных узлов заморожен: значения из этого же незавершённого слоя не используются. Время включает все подготовленные узлы, даже если запрошен только центр.

Один запуск с оценёнными внутренними границами переносит их погрешность дальше. Поэтому программа повторяет **весь** расчёт слоёв B раз с разными seed и оценивает SE по B независимым итогам. Общий N путей на подготовленный узел распределяется между B запусками. Это учитывает перенос неопределённости и не обещает ложную точность по одним коротким последним путям. При неделимости N на B число путей отличается на один; итог усредняется по полным запускам.

Полосы ±1,96 SE в графиках являются приближёнными поточечными интервалами, особенно при малом B; гарантированного покрытия 95% программа не утверждает. Для серьёзного исследования используйте больше полных независимых запусков и внешние повторения эксперимента. На одной центральной точке подготовка слоёв может быть дороже всего расчёта обычным MC.

## Задачи для проверки

| Пример | Решение / условия | Зачем нужен |
|---|---|---|
| Нагретая верхняя сторона | Верх 100, остальные стороны 0, f=0; условия можно менять | Понятный рисунок температуры и случайных выходов |
| Полином | u=1000x(1-x)y(1-y), f=-2000[x(1-x)+y(1-y)] | Проверка знака источника; центральная разность здесь точна в узлах |

В примере с нагретой стороной углы равны среднему двух соседних сторон. Внутреннее четырёхсвязное блуждание в углы не попадает. У сеточного решения значения углов тоже не входят в уравнения внутренних узлов.

## Что показать преподавателю

1. **Таблица результата:** значение/ошибка, время, пути и шаги. Время одного запуска не определяет победителя.
2. **Тепловая карта и карта ошибки:** одна цветовая шкала у методов; серое означает «не вычислялось».
3. **Срез:** сравнение с эталоном и неопределённость в рассчитанных точках.
4. **Сходимость:** как среднее в точке меняется с числом путей. Поточечная полоса не является гарантией для всей кривой.
5. **Путь и хвост:** воспроизводимая отдельная иллюстративная траектория; можно выбрать первый визит в узел и увидеть оставшийся вклад.
6. **Слои:** ползунок раскрывает реально полученные слои в порядке подготовки.
7. **3D:** вращаемая поверхность точного решения (если известно всё поле), иначе прямого сеточного решения, и маркеры фактически рассчитанных точек. Тип поверхности подписан отдельно. Для точечного MC поверхность не выдумывается.
8. **Время - точность:** несколько бюджетов и независимых seed; медиана времени, корень из среднего квадрата ошибок. Используйте перекрывающиеся диапазоны ошибки, а не просто сравнивайте одинаковый N.

GIF сеточного решателя показывает реальные состояния после выбранных итераций. Интервалы кадров не обозначают физическое время и не сравнивают скорость алгоритмов. Интерактивные слои показывают средние значения из полных запусков, последовательно открываемые по глубине.

Во вкладке **«Как идёт расчёт»** под пояснением траектории находится **«Сходимость ЛОМ»**: одна история относительной невязки в двух вариантах — линейном и логарифмическом. Меняется только шкала вертикальной оси; горизонтальная ось показывает номер итерации (0 — начальное состояние). Пунктир показывает относительный допуск остановки. Логарифмическая шкала помогает увидеть уменьшение невязки на последних итерациях. Нулевые значения доступны на линейном графике; в логарифмическом они пропускаются с пояснением.

## Воспроизводимые команды

Во вкладке **«Исследование»** строится таблица времени для относительной ошибки
**1%, 5% и 10%** в одной точке. Она доступна сразу после запуска приложения,
без предварительного расчёта на вкладке «Обзор». Уравнение и граничные условия
берутся из левой панели, а сетка и число усреднений задаются в самой вкладке.
По умолчанию исследуется центр. В «Точка и лимиты поиска» можно выбрать другой
внутренний узел, ограничить число путей и время поиска на каждый метод.

Число усреднений — число независимых запусков `R` в серии. Для каждого бюджета
измеряется относительная RMSE отдельных результатов:

$$
\varepsilon_{rel}=\frac{100\%}{|u_*|}
\sqrt{\frac{1}{R}\sum_{r=1}^{R}(u_r-u_*)^2}.
$$

Для ЛОМ перебираются относительные допуски невязки, для вариантов Монте-Карло —
растущие бюджеты путей. Проверяется ошибка значения в точке относительно точного
решения, если оно известно, иначе — относительно прямого сеточного решения.
Порог не подменяется допуском невязки ЛОМ или ошибкой среднего по всем запускам.

Первый подходящий бюджет проверяется новой независимой серией. В ячейку попадает
**среднее время одного запуска этой проверочной серии**, если обе серии прошли
порог. Для детерминированного ЛОМ предварительная проверка выполняется один раз,
а время усредняется по `R` запускам. Подбор бюджета, вычисление эталона и прогрев
исключены из табличного времени; подготовка слоёв включена. Это эмпирическая
оценка на проверенных бюджетах, без гарантии вероятности и глобально минимального
времени. Проверка лимита времени выполняется между запусками решателя.

Недостигнутые пороги остаются пустыми; статус и последние проверенные бюджеты
видны в «Детали исследования». При нулевом эталоне относительная ошибка не
определена, поэтому нужно выбрать другую точку или задачу. Таблицу и отдельные
замеры можно скачать в CSV. Общий экспорт добавляет каталог `research/` с
таблицей, бюджетами, замерами и настройками. Готовый пример для центра на сетке
`n=24` с пятью усреднениями: [таблица времени](examples/research-center/timings.csv).

```sh
# По умолчанию: n=24, центр, N=2048
python -m pdelab run --out runs/center

# Участок 3×3 вокруг центра, не весь квадрат
python -m pdelab run --mode patch --n 24 --walks 1024 --out runs/patch

# Всё поле и проверка ненулевого источника
python -m pdelab run --mode field --problem polynomial --n 16 --walks 512 --out runs/field

# Серия измерений: N для MC, относительный допуск невязки для ЛОМ
python -m pdelab benchmark --mode point --n 24 --repeats 5 --out runs/benchmark-center

# Проверки
python -m pytest -q
```

CLI `--point X Y` принимает индексы узла; Python API решателя использует пары `(y,x)`. В режиме `patch` участок фиксирован вокруг центра; `--point` применим только к режиму `point`. Seed воспроизводит траектории и значения на проверенной конфигурации; время выполнения зависит от нагрузки компьютера. Первая компиляция исключена из измерений. Разные версии библиотек могут менять последовательности RNG и время.

Сеточный метод всегда вычисляет всё поле, даже если нужен один узел. MC вычисляет только запрошенные узлы; слои готовят необходимую внешнюю часть поля. Это намеренная разница реальной стоимости двух подходов.

## Форматы и устройство

Для разработки установите инструменты и используйте единое форматирование:

```sh
python -m pip install -e '.[dev]'
python -m black .
python -m ruff check .
python -m pytest -q
```

В Python-коде одна инструкция занимает отдельную строку. Black форматирует код,
а Ruff проверяет импорты, неиспользуемые имена и сжатые конструкции через `;`.
Для проверки форматирования без изменений используйте `python -m black --check .`.

- `main.py` - запуск одной командой; `app.py` - интерактивное приложение Streamlit.
- `pdelab/problem.py` - постановки, сетка, эталонный прямой решатель.
- `pdelab/reference.py` - единый выбор эталона для таблиц, графиков и экспорта.
- `pdelab/solvers.py` - четыре вычислительных метода и учёт неопределённости.
- `pdelab/experiment.py` - эксперименты и серии замеров.
- `pdelab/research.py` - подбор и проверка времени достижения заданной точности.
- `pdelab/research_ui.py` - настройки и таблица вкладки «Исследование».
- `pdelab/views.py` - PNG, GIF, автономные HTML.
- `tests/` - численные проверки и проверки экспорта.
- `experiment.json` - условия запуска, платформа, времена, показатели. `lod_stopping_rule` фиксирует относительный критерий. В показателях `residual` — абсолютная невязка, `relative_residual` — нормированная, `residual_scale` — норма правой части. В `Result.extras` хранятся обе истории (`residuals`, `relative_residuals`) и `tolerance`.
- `metrics.csv` - таблица в UTF-8 с BOM для табличных редакторов.
- `fields.npz` - `reference` (основной эталон ошибок), `grid_reference` (прямое сеточное решение), `field_reference` (полная поверхность для отображения), source, boundary, points_yx и для каждого метода значения, SE и счётчики. Если точный ответ известен только в центре, остальные элементы `reference` равны NaN; они не выдумываются. Для аналитических задач полное точное поле также сохранено как `exact`.
- В CSV/JSON поля `reference_kind`, `reference_label` и метаданные `reference_policy` фиксируют, относительно чего измерены ошибки.
- `benchmark.csv` - каждый отдельный замер, включая повтор, бюджет и его тип.

`min_observations/max_observations` у слоёв означают число независимых **полных запусков**, а у других MC - число пригодных исходных путей. Это разные единицы наблюдений. Стоимость сравнивается по `seconds`, `walks` и `steps`, а не по этим счётчикам.

Чтобы добавить свою стационарную задачу, используйте `Problem.from_functions(n, source, boundary, exact=None)` и `solve`. Нельзя просто подставить нелинейный коэффициент k(u) или нелинейную правую часть в текущую формулу случайного блуждания: для такой задачи нужна отдельная математическая конструкция.

## Замороженная переменная проводимость

`pdelab.FrozenOperator` задаёт общую линейную систему
`−div(k grad u) + σu = b` на единичном квадрате с Дирихле.
Это основа для последующего замораживания `k(u)`; нелинейные итерации и
взвешенные случайные блуждания пока не добавлены в интерфейс приложения.

```python
import numpy as np
from pdelab import FrozenOperator

n = 24
x, y = np.meshgrid(np.linspace(0, 1, n + 1), np.linspace(0, 1, n + 1))
operator = FrozenOperator.from_nodes(k=1 + x + y, b=1, boundary=x + y, sigma=0.5)
u = operator.solve()
probabilities, reward, killing = operator.mc_coefficients()
```

Массивы узлов индексируются `[y,x]`; `b`, `boundary`, `sigma` допускают скаляры
в `from_nodes`, а `k` задаётся полным массивом. На гранях используется
арифметическое среднее соседних положительных значений `k`, дающее второй
порядок на гладких полях. Разрывные материалы требуют отдельной модели.
Хранятся неизменяемые копии `wx` формы `(n+1,n)` и `wy` формы `(n,n+1)` —
веса `k_face/h²`, а также узловые `sigma`, `b`, `boundary` формы `(n+1,n+1)`.
Этот формат можно использовать при новых шагах времени и замораживании:
нужно создавать новый оператор с обновлёнными коэффициентами. Поддерживается
только Дирихле; неположительная проводимость и отрицательная реакция отвергаются.

`apply(u)` возвращает внутреннее поле оператора, `fluxes(u)` — ориентированные
потоки по граням (при смене направления знак меняется). `assemble()` независимо
собирает CSR-матрицу и правую часть с перенесёнными значениями Дирихле;
`solve()` использует прямой разреженный решатель. Для положительных весов и
неотрицательной реакции матрица симметрична и положительно определена:
её квадратичная форма — сумма весов квадратов разностей на внутренних рёбрах,
граничных вкладов и `sigma*u²`. CG не используется.

`mc_coefficients()` возвращает вероятности соседей в порядке
`(y+1,x), (y-1,x), (y,x+1), (y,x-1)`, награду `b/d` и вероятность завершения
с нулевой выплатой `sigma/d`. Граничные соседи включены в сумму `d`; после
перехода на них выплачивается Дирихле. При `sigma=0` завершение обеспечивает
достижение границы. `FrozenOperator.from_problem(p)` адаптирует прежнюю задачу:
`k=1`, `sigma=0`, `b=-f`, вероятности `1/4`, вклад `−h²f/4`.
Старые решатели сохраняют API постоянного лапласиана; переменные коэффициенты
решаются через `FrozenOperator.solve()`. Общая прогонка
`pdelab.solvers.solve_tridiagonal(A,B,C,rhs)` принимает три массива полной
длины и сохраняет формулы α/β; крайние внешние значения считаются нулевыми,
ненулевые условия предварительно переносятся в правую часть.
