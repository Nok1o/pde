# PDE Lab: сеточный метод и Монте-Карло

Исследовательская программа для **Δu = f в единичном квадрате или кубе**. В 2D и 3D доступны Дирихле, Нейман и Робин. Есть ЛОМ, Монте-Карло, сравнение с точным решением, графики и русскоязычный интерактивный интерфейс. По умолчанию вычисляется **одна точка в центре**.

Стационарные режимы решают задачи Пуассона в квадрате и кубе, включая смешанные условия Дирихле, Неймана и Робина. Режимы «Теплопроводность» и «Нелинейная теплопроводность» решают параболические задачи в квадрате с физическим временем и условиями Дирихле. Уравнение Бюргерса пока не реализовано. Итерации внутреннего линейного решателя не являются физическим временем.

## Стационарные исследования

В режимах Дирихле и смешанных границ 2D/3D доступны сравнение и исследование
времени достижения 1/5/10% с независимой проверкой. WoS подключён для Дирихле
в квадрате и кубе; MC на сгущённой сетке — также для смешанных границ.
Условия применимости, формулы, реконструкция входных данных и команды
воспроизведения: [docs/stationary-methods.md](docs/stationary-methods.md).
Неподдерживаемые методы явно исключены, замены алгоритмов под прежним именем нет.

## Нелинейная теплопроводность — issues #12 и #13

`python main.py` → **Режим → Нелинейная теплопроводность**:
`u_t = div((1+αu²) grad u) + F`, `C=1`, Дирихле, α≥0.
Реализованы Picard с релаксацией и направленными прогонками, независимый
Newton-эталон и MC внутри Picard с независимой проверкой остановки.
Физические слои, внешние и внутренние итерации сохраняются отдельно.

Есть формулы, сравнение с аналитическим решением, поля/ошибки, история во
времени, нелинейная невязка, таблица 1/5/10% и экспорт CSV/JSON/NPZ/HTML/ZIP.
Разброс MC оценивается по независимым повторам **всей** цепочки; запрос одной
точки не исключает подготовку полного поля. Несошедшиеся расчёты явно отмечаются.

```sh
python -m pdelab.nonlinear_cli run --n 8 --alpha .5 --T .1 --repeats 4
python -m pdelab.nonlinear_cli targets --n 8 --repeats 16
python -m pdelab.nonlinear_cli study --repeats 16 --seed 20261110
```

Подробности и ограничения — [docs/nonlinear.md](docs/nonlinear.md).
Количественные результаты по α=0/0.5/2, сеткам, шагам, бюджетам и релаксации —
[docs/nonlinear-study.md](docs/nonlinear-study.md). Пространственный контроль
показывает второй порядок, временной — первый. Для малых сеток основная
ошибка может быть сеточной: увеличение числа путей её не устраняет.

## Нейман и Робин — issues #7 и #9

Запуск прежний: `python main.py`. В 2D или 3D выберите **«Граничные условия» →
«Смешанные I / II / III»**. Тип задаётся отдельно для каждой стороны квадрата
или каждой из шести граней куба (`x0, x1, y0, y1, z0, z1`):
`u=g`, `∂u/∂n=g` или `∂u/∂n+κu=r`, `κ≥0`.
Доступны ЛОМ, обычный MC, точный эталон, интерактивное поле, траектория с
граничными событиями и серии «время — ошибка». Можно выбрать любой узел,
включая границу. Готовые полином и гладкий пример показывают свои формулы;
в режиме «Свои данные» задаются постоянные источник и граничные данные.

В 3D ЛОМ делает прогонки по x, y и z; MC отражается на Неймане и частично
поглощается на Робине. Доступны точки на гранях, рёбрах и в углах, срезы
`xy/xz/yz`, пространственная траектория и ZIP с CSV, JSON, NPZ и HTML.
Готовые примеры допускают `n ≤ 64`; свои данные — `n ≤ 16`, поскольку для
них нужен прямой сеточный эталон. В API данные и κ могут быть массивами на
гранях: `x`-грани `[z,y]`, `y`-грани `[z,x]`, `z`-грани `[y,x]`.

```sh
python -m pdelab.boundary_cli3d run --x0 neumann --z1 robin --n 16 --point 0 8 8
python -m pdelab.boundary_cli3d run --n 8 --mode slice --plane yz --index 0
python -m pdelab.boundary_cli3d benchmark --n 16 --methods lod_serial --repeats 5
```

Чистый Нейман поддержан прямым решателем и ЛОМ с проверкой баланса и нулевым
средним по контрольным объёмам. MC для чистого Неймана явно недоступен.
Контрольное приближение, хвосты и слои из режима Дирихле пока не перенесены;
MC на сгущённой сетке доступен также со смешанными границами.
Вывод схемы, критерии остановки, углы, ограничения и команды CLI —
в [docs/boundaries.md](docs/boundaries.md).


## Третья пространственная ось — issues #5 и #6

В `python main.py` переключите **«Размерность задачи» → «3D»**. Это задача
в единичном кубе, где решение зависит от трёх координат. Старая вкладка с
графиком высоты двумерного решения теперь называется «Поверхность».

Реализованы отдельные 3D-модули: сетка и эталон в `pdelab/problem3d.py`,
решатели в `pdelab/solvers3d.py`, эксперименты и экспорт в
`pdelab/experiment3d.py`. Контракт: координаты пользователя `(x, y, z)`,
индексы массивов и внутренние списки точек `[z, y, x]`. Все оси содержат
`n+1` узлов с шагом `h=1/n`. Описанный далее исходный режим **«Дирихле»**
задаёт шесть граней согласованной функцией, в том числе на рёбрах и в углах.
Для смешанных условий используются `boundary3d.py`, `boundary_solvers3d.py`
и `boundary_experiment3d.py`; их схема описана в [docs/boundaries.md](docs/boundaries.md).

Два метода решают одну семиточечную систему:

$$
\Delta_h u_i=\frac{\sum_{j\sim i}u_j-6u_i}{h^2}=f_i,
\qquad u_i=\frac{1}{6}\sum_{j\sim i}u_j-\frac{h^2f_i}{6}.
$$

- **ЛОМ:** вычислить невязку → прогонки по x, y, z → добавить поправку →
  проверить относительную невязку с учётом граничной правой части.
- **MC:** выбрать одного из шести соседей с вероятностью 1/6; в каждом
  внутреннем узле накопить `−h²f/6`; при первом попадании на грань добавить
  `g`. Для запроса на границе сразу возвращается известное значение без путей.

Для постоянного параметра прогонок множитель ошибки пространственной моды:

$$
q=1-\frac{\tau(\lambda_x+\lambda_y+\lambda_z)}
{(1+\tau\lambda_x)(1+\tau\lambda_y)(1+\tau\lambda_z)}.
$$

В `splitting_parameter3d` параметр τ выбирается численным minimax-поиском на
512 логарифмически распределённых значениях. Проверяются крайние сочетания
собственных значений одномерных операторов. Это параметр итерационного
решателя, а не физический шаг времени. Параллельный ЛОМ, хвосты и слои в 3D
не реализованы; вызов неподдерживаемого метода завершается явной ошибкой.

Первый запуск: **синус, n=16, одна точка в центре, 2048 путей**.
Для проверки порядка координат переключитесь на линейное поле
`u=1+2x+3y+5z` и нецентральную точку. Константа `u=7` проверяет отсутствие
шума на постоянных данных. Срезы `xy/xz/yz` показывают решение и абсолютную
ошибку с общей цветовой шкалой у методов. Неизвестные узлы MC остаются пустыми.
Можно рассчитывать одну точку, участок 3×3×3, плоскость или всё поле.

Эталон в таблицах и графиках — аналитическое решение. При `n <= 16`
дополнительно строится независимый разреженный сеточный эталон для диагностики;
его ошибка сохраняется как `rmse_grid`. При больших n прямая факторизация
не выполняется. Размер ограничен `n <= 64` до выделения массивов; показанный
резерв памяти относится к плотным массивам, без JIT, графиков и sparse LU.
Стоимость полного MC растёт с числом запрошенных узлов: по умолчанию выбран центр.
Интерактивный MC ограничен 2 млн траекторий и 50 млн шагов по верхней оценке
ожидаемой суммарной длины. Для точки эта оценка равна
`3 × min(x(n−x), y(n−y), z(n−z))` шагов на путь, где x/y/z — индексы узла.
Граничные запросы путей не требуют. При превышении лимита кнопка расчёта
отключается; можно уменьшить запрос или использовать CLI, где этих лимитов нет.
Это ограничение объёма интерактивной работы, а не гарантия времени выполнения.

Во вкладке **«Исследование»** можно менять сетку, точку и число усреднений.
Для каждой цели 1/5/10% MC сначала подбирается с запасом: ошибка предварительной
серии должна быть ≤ 0,5/2,5/5% соответственно. Для детерминированного ЛОМ
достаточно полного целевого порога. Затем бюджет фиксируется и проверяется независимой контрольной серией. Провал
контрольной серии не публикует подтверждённое время: вместо `None` интерфейс
показывает причину, выбранный бюджет и ошибки обеих серий. Повторный подбор
по контрольным данным не выполняется. Сравнивается среднее относительных ошибок отдельных запусков, а не ошибка их среднего.
Это экспериментальная оценка, а не вероятностная гарантия. На синусе остаётся
погрешность сетки, поэтому не любой процент достижим на выбранном n.
Несходимость при более строгом допуске не отменяет проверку ранее найденных
бюджетов. Подбор и проверка имеют отдельные одинаковые лимиты времени на метод.
Если лимит проверки исчерпан, бюджет и последняя полная ошибка сохраняются,
но подтверждённое время не публикуется. Незавершённая серия не считается полным повтором.

## Четыре метода

| Метод | Что реализовано | Что сравнивать |
|---|---|---|
| ЛОМ | Факторизованная поправка по невязке; последовательные прогонки | Время до заданной невязки |
| Монте-Карло | Независимые блуждания от каждой запрошенной точки до границы | RMSE, относительная ошибка, число шагов, время |
| MC, хвосты | Из каждого пути берётся хвост после первого посещения другой целевой точки | Точность при том же бюджете путей и время при сопоставимой ошибке |
| MC, слои | Расчёт от границы внутрь; пути останавливаются на завершённых слоях | Сокращение длины пути с учётом подготовки и переноса неопределённости |

Название «ЛОМ» в интерфейсе обозначает выбранный для стационарной задачи решатель с расщеплением по направлениям. Это **конкретная факторизованная итерационная схема**, а не заявление о реализации любой схемы ЛОМ из литературы. Согласуйте с преподавателем именно эту формулу, если требуется определённая учебная схема.

### Общая дискретизация и знак источника

Имеется n интервалов по каждой оси, h = 1/n, (n+1)² узлов. Массивы индексируются `[y, x]`.

```text
Lh u = (u[x+h,y] + u[x-h,y] + u[x,y+h] + u[x,y-h] - 4u[x,y]) / h² = f
u[x,y] = среднее четырёх соседей - h² f[x,y] / 4
```

Все пять методов решают одну разностную задачу. **Основной эталон в таблицах и графиках — точное аналитическое решение**, если оно известно для выбранных точек. Это полином, синус и линейное поле; для постоянных температур сторон при f=0 также известен точный ответ в центре — среднее четырёх сторон. При стандартных условиях он равен 25.

Если точное решение для всего выбранного набора точек в программе не задано, используется прямое сеточное решение `scipy.sparse.linalg.spsolve`. Тип эталона всегда подписан. Не смешиваем разные эталоны внутри одной RMSE: например, для участка вокруг центра в примере с нагретым краем используется сеточный эталон для всех девяти точек.

В единой таблице показаны значение (для одной точки), время, RMSE, относительная ошибка, новые пути, шаги и итерации. Относительная ошибка `relative_error_pct` = 100 × ‖u − эталон‖₂ / ‖эталон‖₂ по запрошенным точкам. Для одной точки это 100 × |u − эталон| / |эталон|. Если эталон равен нулю во всех выбранных точках, процент не определён (пустое значение в CSV/JSON, прочерк в HTML); используйте RMSE. Это отношение норм, а не среднее поточечных процентов: нулевые значения в части узлов не вызывают деления на ноль.

При сравнении с аналитическим решением ошибки включают пространственную погрешность сетки. Поэтому у ЛОМ на синусе ошибка останется даже при очень малой невязке. `rmse_grid` сохранён в сырых данных для проверки решателя относительно прямого решения той же сеточной системы; это не оценка погрешности сетки. Отдельной таблицы диагностики нет. Максимальная ошибка и SE исключены из таблиц; неопределённость MC по-прежнему рассчитывается для поясняющих графиков.

Прямой решатель используется для независимой диагностики и при наличии точного решения. Его время записывается отдельно и не считается временем какого-либо исследуемого метода. Когда точный ответ известен только в центре, полная фоновая поверхность остаётся сеточной и подписана отдельно; ошибки в центре считаются к точному ответу.

### Базовый решатель

Начальное внутреннее поле равно нулю, граничные значения заданы точно. На каждом шаге:

```text
r = Lh u - f
τ = h / (2π)
(I - τ Lx) v = τ r
(I - τ Ly) δ = v
u ← u + δ
```

Поправка на границе равна нулю. Каждая из двух систем распадается на одномерные трёхдиагональные системы, решаемые прогонкой. Линии внутри прохода и два прохода выполняются последовательно. Обновление эквивалентно `(I-τLy)(I-τLx)δ = τr`; неподвижная точка удовлетворяет исходной системе `Lh u=f`. Здесь нет дополнительного стационарного смещения от расщепления. Критерий остановки: `‖b − A u‖∞ / ‖b‖∞ ≤ tol`; недостигнутая точность не выдаётся за успешный расчёт.

Здесь `A` — матрица для внутренних неизвестных (`−Lh` с нулевой границей), а `b` содержит `−f` и известные граничные значения, перенесённые в правую часть с коэффициентом `1/h²`. Поэтому нормировка работает и при `f = 0`. При нашем нулевом начальном внутреннем поле `‖b‖∞` совпадает с начальной абсолютной невязкой. Если `b = 0`, начальное поле сразу является решением и итерации не нужны. Деления на ноль и искусственного абсолютного порога нет.

`tol` — безразмерная доля между 0 и 1: например, `1e-2` означает 1%, а значение по умолчанию `1e-7` означает 0,00001%. Это относительная невязка уравнения, не относительная ошибка решения в основной таблице. В серии используются допуски `1e-2`, `1e-4`, `1e-6`, `1e-8`. Увеличение `max_iter` не отменяет проверку сходимости. Монте-Карло по-прежнему останавливается по фиксированному числу путей.

Это не оптимизированный промышленный решатель: τ фиксирован, число итераций зависит от сетки и допуска. Реализация проверена сравнением с прямым решением той же сеточной системы.

Прогонка в `_solve_line` записана через коэффициенты α и β, как в
[описании метода](https://ru.wikipedia.org/wiki/Метод_прогонки):

$$
A_i v_{i-1}+B_i v_i+C_i v_{i+1}=F_i,
\qquad v_i=\alpha_{i+1}v_{i+1}+\beta_{i+1}.
$$

Прямой ход:

$$
\alpha_{i+1}=\frac{-C_i}{A_i\alpha_i+B_i},
\qquad
\beta_{i+1}=\frac{F_i-A_i\beta_i}{A_i\alpha_i+B_i}.
$$

Для наших проходов `a = c = -q`, `b = 1 + 2*q`, где `q = τ/h²`.
`rhs_value` соответствует `F_i`: на проходе по x это `τ * residual`,
на проходе по y — результат первого прохода.

В коде внутренние узлы одной линии нумеруются с 0 до `size - 1`.
Поправка на обоих концах линии равна нулю: начинаем с `alpha[0] = beta[0] = 0`,
а обратный ход — с `v[size - 1] = beta[size]`.
Далее восстанавливаем значения по `v[i] = alpha[i + 1] * v[i + 1] + beta[i + 1]`.
Эти нулевые условия относятся к поправке; граничные значения исходного поля
уже учтены при вычислении невязки.

### Обычный Монте-Карло

Из каждого внутреннего узла частица равновероятно переходит к одному из четырёх соседей. Один путь даёт:

```text
Y = g(первое попадание на границу) - (h²/4) × сумма f по внутренним посещениям
û = среднее Y по независимым путям
SE = выборочное стандартное отклонение Y / √N
```

Повторные посещения входят в сумму источника. Для Δu=f знак перед суммой отрицательный. Блуждания оценивают **сеточное** решение: увеличение N не убирает пространственную погрешность сетки. Защитный предел длины пути вызывает ошибку, а не обрезает путь и не возвращает смещённый ответ.

### Улучшение 1: хвосты путей

Если путь из A впервые посетил целевой узел B, оставшаяся часть пути даёт одно наблюдение для B. Из полного вклада вычитается накопленный источник до первого посещения B. Каждый исходный путь учитывается для данного узла не более одного раза. Все повторные посещения не считаются независимыми наблюдениями.

Реализация генерирует N новых путей из **каждой** целевой точки, как обычный MC, в том же порядке и с тем же seed. Это фиксированный план, а не остановка после случайного достижения квоты. Длина сгенерированных путей одинакова с обычным MC, но другие точки могут получить дополнительные наблюдения. Учёт хвостов сам по себе требует времени; улучшение проверяется по кривой «время - ошибка» при разных N.

Для **одной точки** дополнительных наблюдений нет: оценка точно совпадает с обычным MC. Оценки разных точек коррелированы, потому что могут использовать один исходный путь; их нельзя считать независимыми при расчёте неопределённости интеграла по полю.

### Улучшение 2: слои от границы

Сначала известна настоящая граница. Затем вычисляются все узлы первого внутреннего слоя, второго и так далее до самой глубокой цели. Во время расчёта очередного слоя набор известных узлов заморожен: значения из этого же незавершённого слоя не используются. Время включает все подготовленные узлы, даже если запрошен только центр.

Один запуск с оценёнными внутренними границами переносит их погрешность дальше. Поэтому программа повторяет **весь** расчёт слоёв B раз с разными seed и оценивает SE по B независимым итогам. Общий N путей на подготовленный узел распределяется между B запусками. Это учитывает перенос неопределённости и не обещает ложную точность по одним коротким последним путям. При неделимости N на B число путей отличается на один; итог усредняется по полным запускам.

Полосы ±1,96 SE в графиках являются приближёнными поточечными интервалами, особенно при малом B; гарантированного покрытия 95% программа не утверждает. Для серьёзного исследования используйте больше полных независимых запусков и внешние повторения эксперимента. На одной центральной точке подготовка слоёв может быть дороже всего расчёта обычным MC.

## Задачи для проверки

| Пример | Решение / условия | Зачем нужен |
|---|---|---|
| Нагретая верхняя сторона | Верх 100, остальные стороны 0, f=0; условия можно менять | Понятный рисунок температуры и случайных выходов |
| Полином | u=1000x(1-x)y(1-y), f=-2000[x(1-x)+y(1-y)] | Проверка знака источника; центральная разность здесь точна в узлах |

В примере с нагретой стороной углы равны среднему двух соседних сторон. Внутреннее четырёхсвязное блуждание в углы не попадает. У сеточного решения значения углов тоже не входят в уравнения внутренних узлов.

## Что показать преподавателю

1. **Таблица результата:** значение/ошибка, время, пути и шаги. Время одного запуска не определяет победителя.
2. **Тепловая карта и карта ошибки:** одна цветовая шкала у методов; серое означает «не вычислялось».
3. **Срез:** сравнение с эталоном и неопределённость в рассчитанных точках.
4. **Сходимость:** как среднее в точке меняется с числом путей. Поточечная полоса не является гарантией для всей кривой.
5. **Путь и хвост:** воспроизводимая отдельная иллюстративная траектория; можно выбрать первый визит в узел и увидеть оставшийся вклад.
6. **Слои:** ползунок раскрывает реально полученные слои в порядке подготовки.
7. **Поверхность (режим 2D):** вращаемая поверхность точного решения (если известно всё поле), иначе прямого сеточного решения, и маркеры фактически рассчитанных точек. Тип поверхности подписан отдельно. Для точечного MC поверхность не выдумывается.
8. **Время - точность:** несколько бюджетов и независимых seed; медиана времени, корень из среднего квадрата ошибок. Используйте перекрывающиеся диапазоны ошибки, а не просто сравнивайте одинаковый N.

GIF сеточного решателя показывает реальные состояния после выбранных итераций. Интервалы кадров не обозначают физическое время и не сравнивают скорость алгоритмов. Интерактивные слои показывают средние значения из полных запусков, последовательно открываемые по глубине.

Во вкладке **«Как идёт расчёт»** под пояснением траектории находится **«Сходимость ЛОМ»**: одна история относительной невязки в двух вариантах — линейном и логарифмическом. Меняется только шкала вертикальной оси; горизонтальная ось показывает номер итерации (0 — начальное состояние). Пунктир показывает относительный допуск остановки. Логарифмическая шкала помогает увидеть уменьшение невязки на последних итерациях. Нулевые значения доступны на линейном графике; в логарифмическом они пропускаются с пояснением.

## Воспроизводимые команды

Во вкладке **«Исследование»** строится таблица времени для относительной ошибки
**1%, 5% и 10%** в одной точке. Она доступна сразу после запуска приложения,
без предварительного расчёта на вкладке «Обзор». Уравнение и граничные условия
берутся из левой панели, а сетка и число усреднений задаются в самой вкладке.
По умолчанию исследуется центр. В «Точка и лимиты поиска» можно выбрать другой
внутренний узел, ограничить число путей и время поиска на каждый метод.

Число усреднений — число независимых запусков `R` в серии. Для каждого бюджета
измеряется среднее модулей относительных ошибок отдельных результатов:

$$
\varepsilon_{rel}=\frac{100\%}{|u_*|}
\frac{1}{R}\sum_{r=1}^{R}|u_r-u_*|.
$$

Для ЛОМ перебираются относительные допуски невязки, для вариантов Монте-Карло —
растущие бюджеты путей. Проверяется ошибка значения в точке относительно точного
решения, если оно известно, иначе — относительно прямого сеточного решения.
Порог не подменяется допуском невязки ЛОМ или ошибкой среднего по всем запускам.

Для MC предварительный порог вдвое строже целевого (запас по ошибке 50%);
для ЛОМ дополнительного запаса нет. Подходящий бюджет проверяется новой независимой серией. В ячейку попадает
**среднее время одного запуска этой проверочной серии**, если обе серии прошли
свои пороги. Для детерминированного ЛОМ предварительная проверка выполняется один раз,
а время усредняется по `R` запускам. Подбор бюджета, вычисление эталона и прогрев
исключены из табличного времени; подготовка слоёв включена. Это эмпирическая
оценка на проверенных бюджетах, без гарантии вероятности и глобально минимального
времени. Проверка лимита времени выполняется между запусками решателя.

Недостигнутые пороги остаются пустыми; статус и последние проверенные бюджеты
видны в «Детали исследования». При нулевом эталоне относительная ошибка не
определена, поэтому нужно выбрать другую точку или задачу. Таблицу и отдельные
замеры можно скачать в CSV. Общий экспорт добавляет каталог `research/` с
таблицей, бюджетами, замерами и настройками. Готовый пример для центра на сетке
`n=24` с пятью усреднениями: [таблица времени](examples/research-center/timings.csv).

```sh
# По умолчанию: n=24, центр, N=2048
python -m pdelab run --out runs/center

# Участок 3×3 вокруг центра, не весь квадрат
python -m pdelab run --mode patch --n 24 --walks 1024 --out runs/patch

# Всё поле и проверка ненулевого источника
python -m pdelab run --mode field --problem polynomial --n 16 --walks 512 --out runs/field

# Серия измерений: N для MC, относительный допуск невязки для ЛОМ
python -m pdelab benchmark --mode point --n 24 --repeats 5 --out runs/benchmark-center

# Проверки
python -m pytest -q
```

CLI `--point X Y` принимает индексы узла; Python API решателя использует пары `(y,x)`. В режиме `patch` участок фиксирован вокруг центра; `--point` применим только к режиму `point`. Seed воспроизводит траектории и значения на проверенной конфигурации; время выполнения зависит от нагрузки компьютера. Первая компиляция исключена из измерений. Разные версии библиотек могут менять последовательности RNG и время.

Сеточный метод всегда вычисляет всё поле, даже если нужен один узел. MC вычисляет только запрошенные узлы; слои готовят необходимую внешнюю часть поля. Это намеренная разница реальной стоимости двух подходов.

## Замороженная переменная проводимость

`pdelab.FrozenOperator` задаёт общую линейную систему
`−div(k grad u) + σu = b` на единичном квадрате с Дирихле.
Это основа для последующего замораживания `k(u)`; нелинейные итерации и
взвешенные случайные блуждания пока не добавлены в интерфейс приложения.

```python
import numpy as np
from pdelab import FrozenOperator

n = 24
x, y = np.meshgrid(np.linspace(0, 1, n + 1), np.linspace(0, 1, n + 1))
operator = FrozenOperator.from_nodes(k=1 + x + y, b=1, boundary=x + y, sigma=0.5)
u = operator.solve()
probabilities, reward, killing = operator.mc_coefficients()
```

Массивы узлов индексируются `[y,x]`; `b`, `boundary`, `sigma` допускают скаляры
в `from_nodes`, а `k` задаётся полным массивом. На гранях используется
арифметическое среднее соседних положительных значений `k`, дающее второй
порядок на гладких полях. Разрывные материалы требуют отдельной модели.
Хранятся неизменяемые копии `wx` формы `(n+1,n)` и `wy` формы `(n,n+1)` —
веса `k_face/h²`, а также узловые `sigma`, `b`, `boundary` формы `(n+1,n+1)`.
Этот формат можно использовать при новых шагах времени и замораживании:
нужно создавать новый оператор с обновлёнными коэффициентами. Поддерживается
только Дирихле; неположительная проводимость и отрицательная реакция отвергаются.

`apply(u)` возвращает внутреннее поле оператора, `fluxes(u)` — ориентированные
потоки по граням (при смене направления знак меняется). `assemble()` независимо
собирает CSR-матрицу и правую часть с перенесёнными значениями Дирихле;
`solve()` использует прямой разреженный решатель. Для положительных весов и
неотрицательной реакции матрица симметрична и положительно определена:
её квадратичная форма — сумма весов квадратов разностей на внутренних рёбрах,
граничных вкладов и `sigma*u²`. CG не используется.

`mc_coefficients()` возвращает вероятности соседей в порядке
`(y+1,x), (y-1,x), (y,x+1), (y,x-1)`, награду `b/d` и вероятность завершения
с нулевой выплатой `sigma/d`. Граничные соседи включены в сумму `d`; после
перехода на них выплачивается Дирихле. При `sigma=0` завершение обеспечивает
достижение границы. `FrozenOperator.from_problem(p)` адаптирует прежнюю задачу:
`k=1`, `sigma=0`, `b=-f`, вероятности `1/4`, вклад `−h²f/4`.
Старые решатели сохраняют API постоянного лапласиана; переменные коэффициенты
решаются через `FrozenOperator.solve()`. Общая прогонка
`pdelab.solvers.solve_tridiagonal(A,B,C,rhs)` принимает три массива полной
длины и сохраняет формулы α/β; крайние внешние значения считаются нулевыми,
ненулевые условия предварительно переносятся в правую часть.

## Контрольное приближение MC и профилирование

Метод `mc_control` строит прямое решение на грубой сетке и билинейно
интерполирует его на рабочую. По умолчанию грубая сетка имеет `max(4, n//4)`
интервалов. Параметр `--coarse-n` задаёт её явно. При n=4 сетки совпадают.
Для фиксированного v вычисляются r=f−Δ_h v и граничные значения g−v.
Блуждание оценивает поправку, затем прибавляется v в запрошенных узлах.
Аналитическое решение при построении v не используется.

```python
from pdelab import make_problem, prepare_control, select_points, solve

problem = make_problem("sine", n=32)
control = prepare_control(problem, coarse_n=8)
result = solve(problem, select_points(32), "mc_control", control=control)
```

Объект `control` содержит неизменяемые снимки и проверяет соответствие задаче.
При передаче готового объекта `elapsed` учитывает запрос, а стоимость первоначального
построения доступна в `extras["control_build_seconds"]`. Без готового объекта
`elapsed` включает подготовку, отдельно доступную в `preparation_seconds`.
`path_seconds` измеряет вычислительное ядро путей. Для K повторных запросов полная
стоимость равна стоимости построения плюс сумма времён запросов.

```powershell
python -m pdelab run --problem sine --n 32 --coarse-n 8 --no-gifs
python -m pdelab study --problem sine --n 32 --mode patch --repeats 5 --max-walks 4096 --out runs/study
python -m benchmarks.profile_kernels --out runs/profile.json
python -m benchmarks.kernel_breakdown
python -m benchmarks.accuracy_matrix --out runs/accuracy
```

В командах используется Python активированного venv. Подбор бюджета использует
свою серию seed и половину целевой ошибки для MC. Первая прошедшая подбор конфигурация проверяется независимой
серией один раз для каждого порога. Неудачная проверка сохраняется в отчёте.
Для участка и поля усредняется относительная L1-ошибка каждого запуска: сумма модулей ошибок по узлам, делённая на сумму модулей эталона. Нулевые узлы не исключаются.
Дорогая матрица исследований запускается отдельно от тестов.
Результаты и ограничения измерений описаны в `benchmarks/REPORT.md`.


## Линейная теплопроводность — issue #10

В интерфейсе выберите **«Режим» → «Теплопроводность»**. Задаются `a²`,
шаг физического времени `dt`, конечное время `T` и отдельный допуск внутреннего
линейного решения. Таблица различает номер временного слоя, действительное `t`,
размер шага и число итераций внутри слоя. Доступны временной профиль центра,
поле и ошибка в выбранный момент, независимое прямое решение и ZIP для скачивания.
Стационарные режимы 2D/3D доступны через переключатель «Стационарный».

Модель: `u_t = a² Δu + F(x,y,t)`, `u(x,y,0)=u₀`, Дирихле `u=g(x,y,t)`.
Используется неявный Эйлер:

```text
(I − dt·a²·Lh) u^(m+1) = u^m + dt·F(x,y,t_(m+1)).
```

Начальное поле должно совпадать с границей при `t=0`. Источник и граница
вычисляются в новом физическом времени. Если `T` не кратно `dt`, последний
шаг сокращается; при `T=0` возвращается только начальное поле.

Прямой решатель независимо собирает матрицу через сумму Кронекера и использует
разреженную LU-факторизацию. Она переиспользуется только при том же размере
шага; для последнего неполного шага строится новая матрица.
Итерационный решатель использует факторизованные поправки к **исходной**
линейной системе слоя. Если `c=dt·a²`, `Ax=I/2−cLx`, `Ay=I/2−cLy`, то

```text
r = rhs − (I − cLh)u
(I + qAx)(I + qAy) δ = 2q r
u ← u + δ
```

Безразмерный параметр внутренней итерации `q` выбирается по спектру
одномерного оператора. Он не является `dt`. Произведение факторов используется
как предобусловливатель, а не как замена матрицы Эйлера: итерации продолжаются до
`||rhs−Au||∞ / ||rhs||∞ ≤ tol`, с учётом Дирихле в правой части. При нулевой
правой части принимается только нулевая невязка. Недостижение допуска явно
завершает расчёт ошибкой с номером слоя и временем.

Два примера с точными решениями:

- `decay`: `u*=exp(−2π²a²t)sin(πx)sin(πy)`, нулевые источник и граница.
- `manufactured`: `u*=1+x+y+t(1+x)+exp(t)x(1−x)y(1−y)`, ненулевые временные
  источник и граница; `F` вычислено подстановкой в уравнение.

```sh
python -m pdelab heat --problem decay --n 24 --dt 0.01 --T 0.2 --out runs/heat
python -m pdelab heat --problem manufactured --method direct --dt 0.013 --T 0.04
python -m pdelab heat-study --out runs/heat-study.csv
```

`heat-study` разделяет ошибки: пространственный порядок относительно
аналитического решения при очень малом `dt`; временной порядок относительно
точного **полудискретного** синусоидального решения (без пространственной ошибки);
ошибка внутреннего решения относительно прямого решателя на тех же шагах.
Ожидаемые порядки — около 2 по `h` и около 1 по `dt`. Для постоянных данных
стационарный предел соответствует старому API со знаком `f=−F/a²`.

```python
from pdelab import HeatProblem, solve_heat

problem = HeatProblem.from_functions(
    n=16, a2=0.5,
    initial=lambda x, y: 0,
    source=lambda x, y, t: 1,
    boundary=lambda x, y, t: 0,
)
result = solve_heat(problem, dt=0.01, T=0.2, tol=1e-10)
# result.times[m] — физическое время; result.iterations[m] — внутренние итерации.
```

`fields.npz` хранит все физические времена, поля `[time_index,y,x]`, точное
решение, если задано, и диагностику слоёв. `layers.csv` содержит действительное
`t`, `dt`, число итераций, невязку, значение центра и RMSE к точному решению.
`experiment.json` фиксирует метод, параметры, критерий остановки и версии;
`interactive.html` автономен, с временным профилем и до 21 среза поля, все слои
доступны в NPZ. ZIP содержит эти же файлы. Время расчёта измеряется после JIT,
включает подготовку матриц и не включает визуализацию и экспорт.
Для ограничения памяти сохраняемая история ограничена 16 млн значений и
10000 шагами; уменьшите сетку или число временных шагов при превышении.

## Монте-Карло в физическом времени — issue #11

В режиме «Теплопроводность» доступны вкладки **«Монте-Карло»** и
**«Исследование по времени»**. Можно выбрать конечное время, точку, бюджет
полных траекторий и seed. Исследование не требует предварительного расчёта
сеточного поля. В CLI:

```sh
python -m pdelab heat-mc --n 16 --dt 0.001 --T 0.01 --point 8 8 --walks 4096 --out runs/heat-mc
python -m pdelab heat-mc-study --n 16 --dt 0.001 --T 0.01 --repeats 5 --max-walks 16384 --out runs/heat-mc-study
python -m benchmarks.heat_mc_costs --out runs/heat-mc-costs.csv
```

Пространственно-временная траектория решает ту же систему неявного Эйлера.
При `λ=a²·dt/h²` и `d=1+4λ` в каждом внутреннем узле текущего слоя:

- добавляется источник `dt·F(x,y,t)/d`;
- с вероятностью `λ/d` выполняется каждый из четырёх пространственных переходов;
- с вероятностью `1/d` путь переходит в тот же узел предыдущего слоя;
- при достижении границы выплачивается `g` в достигнутом физическом времени;
  при достижении `t=0` выплачивается известное начальное поле `u₀`.

Веса получаются через `FrozenOperator` с `k=a²·dt`, `sigma=1`. Вероятность
`sigma/d` здесь означает переход назад по времени, а не завершение с нулевой
выплатой. Источник не добавляется второй раз при временном переходе.
Последний неполный шаг использует собственные веса и настоящее время `T`.

Это самостоятельный MC: неизвестные предыдущие поля не вычисляются и не
берутся из ЛОМ, прямого или точного решения. Сохраняются только известные
начальные данные, источник и граница во всех нужных временах. Их подготовка
**включена** в полное время; память этих буферов также показывается. Одна
независимая траектория включает все свои пространственные и временные
переходы; SE считается по полным выплатам траекторий, с учётом их внутренней
корреляции. Оценённых предыдущих полей и переноса ошибки между такими полями
в этой реализации нет. Подготовка известных данных масштабируется с числом
слоёв и узлов даже для запроса одной точки — она не бесплатна.

Отдельный API `heat_mc_step(problem, previous, dt, t, ...)` — **диагностика
одного шага с детерминированно заданным предыдущим полем**, а не самостоятельный
расчёт истории. Подготовка переданного поля исключена из этого диагностического
замера и должна учитываться вызывающим кодом. В интерфейсе диагностика
проверяет только первый шаг, где `previous=u₀` известно. Пример:

```python
from pdelab import make_heat_problem, solve_heat_mc, heat_mc_step

problem = make_heat_problem("manufactured", n=12)
result = solve_heat_mc(problem, dt=0.013, T=0.04,
                       points=[[7, 4]], walks=4096, seed=42)
step = heat_mc_step(problem, problem.initial, dt=0.013, t=0.013,
                    points=[[7, 4]], walks=4096, seed=42)
# Python: точки (y,x); CLI --point: X Y.
```

`max_transitions` ограничивает **все** переходы отдельной траектории. Превышение
вызывает ошибку и не возвращает усечённую оценку. Временная сетка ограничена
10000 шагами, история коэффициентов — 16 млн узлов, как у сеточного режима.
Отдельный интерактивный запуск ограничен верхней оценкой 50 млн ожидаемых переходов;
CLI сохраняет явный предел на отдельный путь. Предел времени исследования
проверяется между полными запусками, поэтому один запуск может его превысить.

Исследование перебирает допуски ЛОМ и бюджеты MC, усредняя обычную относительную
ошибку **отдельных полных запусков до T** относительно аналитического решения, если оно задано,
иначе — прямого решения той же временной сетки. MC подбирается до половины
целевой ошибки; ЛОМ — до полного порога. После подбора порог проверяется
одной окончательной серией независимых seed на первом прошедшем подбор
бюджете. Провал фиксируется как `not_confirmed`: этот порог больше не участвует
в подборе, его бюджет и обе ошибки сохраняются, а время остаётся пустым.
В таблицу попадает среднее полное время одного
запуска проверочной серии только при прохождении обеих серий. Неуспешные
пороги отображаются с причиной, бюджетом и фактическими ошибками; сеточная и временная ошибки могут мешать
достижению порога даже при бесконечном бюджете MC. Это эмпирический подбор,
а не гарантия вероятности или глобально минимального времени.

Экспорт MC содержит `queries.csv`, `queries.npz` и `experiment.json`: значения,
SE, координаты, действительные времена, seed, лимиты, полное время, подготовку,
время траекторий и оба счётчика переходов. `memory_bytes` учитывает главные
численные буферы во время расчёта, а не RSS, временные копии или память JIT.
Исследование сохраняет `settings.json`, `timings.csv`, `trials.csv`; интерфейс
позволяет скачать весь результат исследования в JSON.
Результаты и ограничения сравнения стоимости:
[отчёт](benchmarks/REPORT.md#монте-карло-в-физическом-времени-issue-11).

### Состояние интерфейса и протокол исследования

Активная вкладка и раскрытые панели имеют постоянные ключи. «Рассчитать»
открывает результаты своего режима; запуск исследования сохраняет вкладку
исследования. Формулы открываются отдельной панелью, скачивание готового
файла не перезапускает приложение. Таблица времени дополняется видимыми
бюджетами и ошибками выбранного порога; переключение 1/5/10% не запускает расчёт.

Протокол `pilot_half_target_mean_relative_error_v3` действует для
стационарных 2D/3D, смешанных границ, линейной и нелинейной теплопроводности.
В нелинейном режиме показываются начальный бюджет N₀ на узел и Nmax; это не
общее число путей всей истории. Запас 50% уменьшает риск неудачной проверки,
но не является статистической гарантией. Если даже запас не достигнут на
максимальном бюджете, это отдельный статус, а не утверждение, что полный
целевой порог математически недостижим. Старые сохранённые исследования
помечаются как результаты прежнего протокола. Числовой CSV сохраняет пустое
время неуспеха, статусы и ошибки доступны в подробном экспорте.

Метрика исследований записывается как `mean_run_relative_l1_v1`. Для одной
точки это `mean(100 * abs(u_run-u_exact) / abs(u_exact))`, без квадратов и корня.
Для участка/поля используется `mean_runs(100 * sum(abs(u_run-u_exact)) / sum(abs(u_exact)))`.
Обычные сравнения и графики RMSE остаются отдельной диагностикой. Старый PDF-аудит
и исторические CSV относятся к указанным в них прежним метрикам; их числа не
переименовываются в результаты нового исследования.
