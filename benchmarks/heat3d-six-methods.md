# План общей серии #31

Базовая реализация — main `131dda6` после интеграции групповых методов #47.
Первый пилот четырёх методов хранится в `results/heat3d-pilot` с измеренной
версией `d9eecce`. Новая серия записывается отдельно.

## Зафиксированные малые серии

`heat3d-six-n8.json` задаёт прежние четыре сценария, R=5 и шесть методов.
Основная таблица использует B=128 для обоих групповых методов. Выбор сделан
до измерений. Сетка n=8, H/h=2, dt=0,002, T=0,004, α=0,5, точки,
границы, seed и бюджеты совпадают с пилотом четырёх методов.
Для каждой цели 1/5/10% применяется опубликованный общий протокол подбора
и независимой финальной проверки.

`heat3d-groups-n8.json` отдельно фиксирует N=1024, R=5, seed=31027,
B=1,32,128,512 для двух групповых вариантов и обычные пути для каждого
семейства. Все четыре сценария сохраняются. Каждый повтор заново считает
полную историю и подготовку. Размер группы по результатам этой серии
не выбирается. Завершение полного набора повторов требуется для средней
ошибки и среднего времени успешного расчёта. При отказах публикуется
фактически затраченное время всех попыток с количеством завершённых.
Seed повторов одинаковы между вариантами. При B>1 группировка меняет порядок
случайных выборов, поэтому итерации Пикара и число попыток приёмки могут различаться.

```sh
python -m benchmarks.heat3d_pilot --plan benchmarks/heat3d-six-n8.json --out runs/heat3d-six-n8
python -m benchmarks.heat3d_pilot --plan benchmarks/heat3d-groups-n8.json --out runs/heat3d-groups-n8
```

Порядок методов фиксирован, процессы последовательные, потоки BLAS/Numba=1.
Каждая серия начинается с чистого коммита и завершается проверкой неизменности
исходников. Время полного решателя учитывает подготовку и независимые проверки
Пикара. Пик RSS измеряется на процесс исследования до экспорта и включает
импорт библиотек, JIT и все повторы. Сводки сохраняют затраты подбора отдельно
от времени подтверждённого достижения цели.

## Расширение после оценки стоимости

После обеих малых серий фиксируется отдельный план большей сетки.
Предварительный предел расширения — два сценария и шесть методов, R=5.
Размер сетки, H/h и лимиты выбираются по измеренной стоимости и оценке
рабочей памяти. Основной размер группы B=128 сохраняется.
Причины выбора записываются до запуска вместе с коммитом плана. Все отказы
на большой сетке входят в итоговый отчёт.

После n=8 зафиксирован `heat3d-six-n16.json`. Две малые серии потребовали
470 полных попыток и 42,51 с суммарного времени решателя. Самая долгая попытка
заняла 0,493 с. На n=16 выбраны синус с условиями 1 рода и полином со всеми
границами 3 рода. Они охватывают завершённые и незавершённые малые серии.
Нормированные точки, dt, T, R=5 и B=128 сохранены, coarse_n=8 сохраняет H/h=2.
Пределы путей и переходов увеличены в восемь раз вслед за оценкой роста объёма.
Мягкий предел 5 с на полный запуск, восемь итераций Пикара на слой и
256 МиБ оценки буферов сохранены. План охватывает 12 пар сценарий/метод.

```sh
python -m benchmarks.heat3d_pilot --plan benchmarks/heat3d-six-n16.json --out runs/heat3d-six-n16
```
