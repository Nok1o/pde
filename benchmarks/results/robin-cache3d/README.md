# Отражения в стационарном MC 3D

Полином `u*=1+x+2y+3z+x²+y²+z²`, равномерный куб, `k=1`, сетка с 12 интервалами, центр (6, 6, 6), 512 путей на точку. На одной (x0), трёх (x0, y0, z0) или всех шести гранях заданы условия 3 рода с β=1. На остальных гранях заданы условия 1 рода. В центре аналитическое значение равно 4.75. Решатель получает только источник и граничные данные.

## Какие операции требуют времени

В [профиле исходного MC](baseline.json) использованы функции опубликованной версии `2282b85`. Для каждого набора граней измерены три полных обхода с независимыми seed. Во всех таблицах этого раздела приведены медианы трёх значений каждой колонки.

| Граней 3 рода | Этапов пути | Этапов на границе, % | Предложений наружу, отражённых внутрь | Расчётная доля времени этапов на границе, % |
|---:|---:|---:|---:|---:|
| 1 | 28 136 | 2.07 | 93 | 2.59 |
| 3 | 41 191 | 8.47 | 624 | 10.13 |
| 6 | 104 183 | 16.85 | 3 125 | 19.56 |

Этап начинается в свободном узле с выплаты и заканчивается поглощением или предложением шага. Воспроизведение тех же случайных чисел сохраняет очерёдность посещений и позволяет посчитать число этапов на гранях, рёбрах и в углах. Достижение фиксированного узла приносит конечную выплату. Предложение наружу возможно только после прохождения проверки на поглощение.

Для оценки стоимости отдельно воспроизведены операции этапа в записанных внутренних и граничных узлах. В каждой группе в исходном порядке повторяются чтение выплаты и вероятности, розыгрыш поглощения при положительной вероятности, предложение, проверка фиксированного соседа и его выплата. Для этапов заново генерируются случайные числа, в каждой группе выполнено не менее 250 тыс. обработок. Взвешенная оценка доли равна `N_гр t_гр / (N_гр t_гр + N_вн t_вн)`, где t — замер на событие. Она включает обычную работу этапа на граничных узлах. Раздельное воспроизведение меняет порядок обращений к памяти и исключает зависимость следующей позиции от предыдущего шага. Фактическое время полного обхода измерено отдельно.

| Граней 3 рода | Сборка оператора, мс | Подготовка коэффициентов MC, мс | Полный обход ядра, мс | Внутренний / граничный этап при воспроизведении, нс |
|---:|---:|---:|---:|---:|
| 1 | 0.208 | 0.032 | 0.346 | 12.64 / 16.04 |
| 3 | 0.176 | 0.028 | 0.545 | 12.63 / 15.61 |
| 6 | 0.265 | 0.014 | 1.472 | 12.65 / 15.46 |

Исходные методы один раз за решение делят правую часть и коэффициент поглощения на диагональ. При этом `mc_coefficients()` формирует ещё и массив шести вероятностей на узел, хотя переход уже задан шестью равновероятными предложениями. При n=12 этот массив занимает 105 456 байт. Сборка оператора, подготовка коэффициентов и обход в таблице замерены раздельно с заранее созданными входными данными, прогрев вынесен за таймер.

## Сравнение при заданном бюджете

Четыре варианта используют одинаковые n, Q и N. Каждая пара «набор граней, метод» запускается в отдельном процессе. После прогрева того же решателя на двух путях выполняются три независимых полных расчёта. Входные поля, аналитическая проверка, прогрев и запись файлов вынесены за таймер. Время публичного решателя включает сборку оператора, таблицу отражений при её использовании, обход путей и подготовку выходных полей. Лимит — 144 000 этапов на один путь, размер группы — 32. Число этапов включает поглощения без пространственного шага.

[Фактические повторы](comparison.json) позволяют проверить значения, стандартные ошибки, завершённые и начатые пути, затраченное время и причины отказов. Средняя ошибка в процентах вычислена через `measurement_protocol.query_error` по результатам каждого полного повтора. Неполной серии средняя ошибка не присваивается. Эта диагностика использует заданный N, без подбора бюджета или подтверждения целей 1/5/10%.

У обычного MC публичный таймер включает подготовку, прочерк означает отсутствие отдельного таймера подготовки в этом backend. Пик RSS охватывает весь процесс с импортами и прогревом. Полезная память таблицы соседей при n=12 равна 208 байт. У оптимизированного метода также отпадает отдельный буфер вероятностей на 105 456 байт. Одиночные процессные пики не позволяют различить настолько малые затраты на фоне интерпретатора и JIT.

Для одной грани медианное время скалярного MC с кэшем ниже на 0.069 мс. Для трёх и шести граней оно выше на 0.041 и 0.037 мс. В группе из 32 частиц кэш дал меньшую медиану во всех трёх коротких случаях. Различаются seed и фактические длины независимых путей, запуск выполнен на одной машине, по три повтора. Полученные отношения времени не устанавливают устойчивый выигрыш. Различия ошибок недостаточны для вывода об изменении дисперсии. Большое исследование бюджетов и перенос на временную задачу остаются отдельными этапами.

## Воспроизведение

В проектном окружении, из корня репозитория, выберите новые имена выходных файлов.

```sh
python -m benchmarks.robin_events3d --out runs/robin-profile/baseline.json
python -m benchmarks.robin_cache3d --out runs/robin-profile/comparison.json
```

Для воспроизведения именно исходного профиля первую команду выполняют на версии `2282b85`, скопировав туда из PR файл `benchmarks/robin_events3d.py`. На версии PR та же команда измерит обычный вариант из PR. JSON содержит SHA256 скриптов и функций ядра, версии Python, NumPy, Numba, операционную систему и фактические seed. Стартовые индексы seed-плана для профиля и для сравнения различаются.
