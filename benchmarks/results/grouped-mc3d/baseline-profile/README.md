# Исходный профиль MC перед группировкой

Разведочная серия на опубликованном commit `3bcd7836e4291f101794b9017fa72d254dae9d1a`: 13 сценариев, 5 независимых seed, 65 запусков. Хеши непосредственно профилируемых `_mc3d` и `_walks`, параметры, версии и seed сохранены в metadata.json; полные наблюдения — в warm_trials.csv. Эти ядра не изменены в #29.

При n=32, N=16384, центре медиана полного публичного решения / времени ядра составляла 60.92 / 60.61 мс для синуса с условиями 1 рода и 80.18 / 78.50 мс для полинома с одной гранью 3 рода. Это показало, что крупные запуски ограничены обходом путей, а не подготовкой оператора.

В CSV full_seconds дополнительно включает создание входной тестовой задачи; solver_seconds относится к публичному решателю. Это различие не скрывается при сопоставлении с последующим исследованием. Cold-файлы — отдельные первые вызовы, не стоимость прогретых запусков. particle_lifetimes.json содержит наблюдаемые длины путей и оценку заполненности фиксированных масок; это объяснение выбора уплотняемого массива активных частиц, не доказательство ускорения.

Пороговые выводы о выигрыше нужно брать из основной серии `python -m benchmarks.grouped_mc3d`, где неизменённый обычный MC измеряется заново рядом с групповым методом, с одинаковым протоколом и новым контролем точности. Разведочные времена сюда не подставляются.
