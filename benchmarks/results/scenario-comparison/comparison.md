# Сравнение методов при целях 1%, 5% и 10%

- В одном файле 47 сценариев и 723 строк целей. Для каждого метода показаны все пороги 1%, 5% и 10%, включая проигрыши и отказы.
- Выигрыш MC у ЛОМ есть в стационарной 3D-задаче с запросом одной точки. Он зависит от сетки, точности и объёма запроса; в полной нелинейной временной цепочке ЛОМ быстрее MC.
- Новые методы переноса частиц не меняют этот вывод: counts ускоряет обычный MC в измеренных полных историях, но проигрывает ЛОМ. Детерминированный перенос близок к ЛОМ; малые различия времени не доказывают устойчивого превосходства.
- Основная ошибка для точки: среднее по запускам 100·|u−u*|/|u*|. Это не RMSE и не ошибка усреднённого решения. Для современного запроса поля берётся средняя относительная L2-ошибка. Оба метода должны пройти один порог; их фактические ошибки могут различаться.
- Ускорение K = время ЛОМ / время метода вычисляется только внутри одной серии, при подтверждении цели обоими методами. K>1 — измеренный выигрыш, K<1 — проигрыш. Неудачи не заменяются нулями и не дают коэффициента ускорения.
- Свежая стационарная серия: 7 сценариев, 6 методов, R=10, commit c474bc4. Подбор с запасом 0,8, затем независимый финал без перенастройки. Все расчёты времени на компьютере выполнялись последовательно, в один поток; аудит данных распараллелен.
- Архивы представлены отдельными разделами со своими версиями, R и протоколами. Старые RMS-результаты не переименованы в среднюю относительную ошибку. Между архивами не вычисляются ускорения; повторяющиеся задачи не считаются независимой статистикой.

Ячейка: среднее время финала / фактическая ошибка / бюджет / отношение времени ЛОМ. У неудач указаны фаза, завершённые повторы и затраты; они не считаются временем достижения цели.

## Как воспроизвести

Для демонстрации: python main.py → Стационарный → 3D → Пуассон: синус в кубе → одна точка → центр → Исследование. Начните с n=16 или 32 и цели 5/10%; затем покажите 1% и всё поле, где выигрыш меняется или пропадает.

Настройки новой серии: R=10, seed=42, максимальное N=16384, контрольная сетка 4 для n=8/16, 8 для n=32, 16 для n=64, размер пакета 128. Для поля n=8 максимум N=1024. В интерфейсе список промежуточных бюджетов может быть плотнее; точное воспроизведение таблицы даёт python -m benchmarks.scenario_comparison --output runs/my-comparison. Каталог должен быть новым.

Перенос количества частиц и массы подключён к квазилинейной теплопроводности 3D. В стационарной таблице mc_grouped означает пакеты отдельных траекторий, а не перенос количества. Неподдерживаемые сочетания не заполнены результатами другого решателя.

В одной замороженной системе mass_transport переносит единичную вещественную массу из точки запроса. Для полной истории тот же линейный ответ для всех стартов вычисляется эквивалентной итерацией Якоби с начальным приближением. Оба варианта детерминированы; это не обычный MC и не одинаковая последовательность вычислительных операций.

Синус стационарной задачи: u*=sin(πx)sin(πy)sin(πz), f=−3π²u*, все грани 1 рода. Линейное поле: u*=1+2x+3y+5z, f=0. Временная 3D-модель: c(u)=1+γu², k(u)=1+αu², источник F−σu³; параметры времени и границ приведены у каждого сценария.
