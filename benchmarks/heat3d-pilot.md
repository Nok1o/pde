# Короткая временная серия для #31

Сценарий запускает опубликованный `study_heat3d` отдельно для каждой явно
заданной пары «задача — вариант метода». Все процессы последовательные,
по одному потоку BLAS/Numba. Перед замерами нужно согласовать окно без
параллельных тестов и вычислений на том же компьютере.

```sh
python -m benchmarks.heat3d_pilot --plan benchmarks/heat3d-pilot.json --out runs/heat3d-pilot
```

Код и план фиксируются коммитом до измерения. Укажите новый каталог в
игнорируемом `runs/` или вне рабочей копии. Скрипт проверяет commit, чистоту
дерева и SHA256 исходников до и после серии. Изменение версии прерывает
приёмку серии, уже полученные данные сохраняются.

В плане фиксированы R=5, seed, два бюджета путей, два допуска прогонок,
запас 0,8 и пределы на полный запуск. Общий протокол выбирает бюджет на
предварительных сериях, затем проверяет его новыми полными повторами.
Финальная неудача завершает подбор. Ошибка измеряется против аналитического
решения при T=0,004, каждый повтор проходит два физических слоя.

Начальная сетка n=8 ограничивает стоимость пилота четырёх методов. На ней
проверяются обе функции, центр (0,5; 0,5; 0,5) и нецентральная точка
(0,25; 0,5; 0,75). У полинома та же нецентральная точка сравнивается для всех
граней 1 рода, грани x0 3 рода и всех граней 3 рода при β=1. Координаты
плана — индексы в порядке xyz. H/h=2. Большие сетки, другие H/h, длина истории
и объём запроса относятся к расширению серии после оценки этого пилота.

В каждом JSON сохранён исходный результат общего API с параметрами, seed,
всеми попытками и статусами. `targets.csv` содержит цели 1/5/10%,
`series.csv` — уникальные предварительные/финальные серии,
`trials.csv` — каждый полный запуск. `costs.csv` считает общую работу один
раз на пару «задача — вариант», включая отказы. Суммировать затраты строк
целей нельзя, поскольку одна финальная серия может обслуживать несколько целей.
Неподтверждённая цель имеет пустое время достижения и объяснение статуса.
Разброс `observed_seconds_*` относится к фактически указанной фазе и бюджету.

Время решателя включает подготовку, все слои и проверки. Подготовка уже входит
в общее время. Прогрев, внешние эталоны и экспорт учитываются отдельно.
Измеренный максимум RSS относится к отдельному процессу целого исследования
до экспорта, включая импорт библиотек и JIT. Он находится в `process`
исходного JSON и `costs.csv`. `peak_rss_bytes` отдельных запусков сохраняет
значение API, `workspace_bytes` остаётся оценкой буферов. Временные выбросы
сохраняются. Порядок методов фиксирован и указан в manifest.

График `error-time.png` строится после замеров по полным сериям, включая
предварительные серии и финальные отказы по точности. Неполные серии остаются
в таблицах с причинами. По графику нельзя установить подтверждение цели.

Для общей серии шести методов используется тот же сценарий с новым
зафиксированным планом и версией решателя. Элементы `variants` передают
`method` и необязательные `settings` опубликованному API. После интеграции
группировки в этом списке можно указать несколько размеров группы, сохраняя
число путей отдельным бюджетом. Скрипт проверяет доступность методов до запуска.
Итоговая серия шести методов и закрытие #31 требуют отдельной приёмки.
