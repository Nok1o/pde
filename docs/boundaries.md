# Условия второго и третьего рода: задачи #7 и #9

Реализация для линейной двумерной задачи `Δu=f`, `k=1`, на единичном
квадрате. Для каждой стороны независимо задаются Дирихле `u=g`, Нейман
`∂u/∂n=g` или Робин `∂u/∂n+κu=r`, `κ≥0`.
Внешняя нормаль: слева `−∂x`, справа `+∂x`, снизу `−∂y`, сверху `+∂y`.
Физический поток наружу `q=−k∂u/∂n` переводится явно через
`BoundaryCondition.from_flux(q, conductivity=k)`; сам решатель пока имеет `k=1`.

Обозначения согласованы с [MFEM](https://mfem.org/fem_bc/). Ниже выведена
собственная разностная схема; FEM-дискретизация из этого источника не используется.

## От 1D к 2D

На левой границе в 1D условие `−u′(0)+κu(0)=r` с центральной производной
даёт фиктивный узел `u₋₁=u₁+2h(r−κu₀)`. Подставляя его в `u″=f`, получаем

$$
\left(\frac{2}{h^2}+\frac{2\kappa}{h}\right)u_0
-\frac{2}{h^2}u_1=-f_0+\frac{2r}{h}.
$$

На правой границе аналогично, с внутренним соседом `uₙ₋₁` и внешней
производной `+u′(1)`. При `κ=0` это условие Неймана.

В 2D добавляются обычные тангенциальные соседи. Например, на левой стороне
вне углов:

$$
\left(\frac4{h^2}+\frac{2\kappa}{h}\right)u_{0j}
=\frac{2u_{1j}+u_{0,j-1}+u_{0,j+1}}{h^2}-f_{0j}+\frac{2r_j}{h}.
$$

Это также баланс на узловом контрольном объёме: площадь внутри равна `h²`,
на стороне `h²/2`, в углу `h²/4`. В углу без Дирихле складываются вклады
обеих сторон; два внутренних соседа имеют вес `2/h²`. Дирихле имеет
приоритет в смешанном углу. Два значения Дирихле в одном углу должны
совпадать, иначе данные отвергаются.

Коэффициенты граней берутся из `FrozenOperator` (#8). `BoundaryOperator`
добавляет неизвестные на границе и коэффициенты полуобъёмов; внутренние
строки совпадают с существующим оператором. Один набор `weights`,
`diagonal`, `b`, `fixed` используется ЛОМ и MC. Независимая сборка CSR
проверяется против применения трафарета. При умножении строк на площади
контрольных объёмов матрица симметрична.

## ЛОМ и относительный останов

Пусть `A=Aₓ+Aᵧ`, `Au=b`. Вычисляем невязку `R=b−Au`, затем

$$
(I+\tau A_x)v=\tau R,\qquad
(I+\tau A_y)\delta=v,\qquad u\leftarrow u+\delta,
\quad\tau=\frac{h}{2\pi}.
$$

Первые и последние уравнения прогонки включают множители `2/h²` и `2κ/h`.
Например, слева коэффициенты поправки: `B₀=1+τ(2/h²+2κ/h)`,
`C₀=−2τ/h²`. Нулевая поправка задаётся только на Дирихле. На Неймане и
Робине правая часть поправки берётся из невязки их строк. Прогоночные
коэффициенты вычисляются один раз на решение, рабочие буферы переиспользуются.

Останов: `‖R‖∞ / ‖R₀‖∞ ≤ tol`; начальное внутреннее поле нулевое,
известные Дирихле уже подставлены, поэтому нормировка включает их вклад.
Если начальная невязка нулевая, решение готово сразу. Исчерпание `max_iter`
возвращает `converged=False`; интерфейс не выдаёт такой расчёт за успешный.

## Монте-Карло

Для неизвестного узла строка имеет вид

$$
d_i u_i=\sum_j w_{ij}u_j-f_i+q_i,\qquad
q_i=\sum_{\text{стороны в узле}}\frac{2r}{h},\qquad
s_i=\sum_{\text{стороны в узле}}\frac{2\kappa}{h}.
$$

Вероятности: `Pᵢⱼ=wᵢⱼ/dᵢ`; вклад посещения: `(-fᵢ+qᵢ)/dᵢ`;
поглощение с нулевой дополнительной выплатой: `sᵢ/dᵢ`.
При Неймане путь продолжается, но ненулевой вклад производной сохраняется.
При Робине сначала добавляется вклад, затем определяется поглощение или
продолжение. На Дирихле выплачивается `g`, и путь заканчивается.
Все веса неотрицательны, сумма переходов и поглощения равна единице.
При наличии Дирихле либо положительного Robin-поглощения конечная связная
цепь достигает поглощения с вероятностью 1.

Количество путей задано явно; это не останов по известной ошибке.
`max_steps` — аварийный предел: при его превышении весь вызов завершается
ошибкой, усечённые выплаты не возвращаются. Для чистого Дирихле используется
прежнее ядро MC с тем же seed и теми же траекториями. Хвосты, слои и
контрольный MC для смешанных границ пока недоступны.

## Чистый Нейман

Проверяется именно дискретная совместимость:

$$
\sum_i V_i f_i=\sum_{\partial\Omega} h\,\omega_i g_i,
$$

где `ω=1` вдоль стороны и `ω=1/2` на её концах. Невязка баланса проверяется
относительно суммы модулей слагаемых с допуском `1e-12`. Данные не
проецируются и не исправляются молча. Совместимость непрерывных интегралов
сама по себе не гарантирует точного совпадения их квадратур.

Решение и аналитический эталон нормируются одинаково: `ΣVᵢuᵢ=0`.
Прямой решатель использует расширенную систему с множителем Лагранжа,
а ЛОМ убирает взвешенное среднее после каждой поправки. Сингулярная исходная
матрица не передаётся обычному `spsolve`. Свобода добавления константы и
обработка ядра разобраны в [примере FEniCSx](https://jsdokken.com/dolfinx-tutorial/stable/chapter2/singular_poisson.html).

**Граница MVP #9:** MC для чистого Неймана явно отвергается. Следующая
отдельная задача — вывести вероятностную оценку решения с фиксированным
средним для цепи без поглощения, реализовать прототип и проверить его
смещение/дисперсию. Простое отражение и конечный `max_steps` эту задачу
не решают.

## Запуск и проверки

`python main.py` → **2D → Граничные условия → Смешанные I / II / III**.
Для каждой стороны доступны свой тип и κ. В готовых примерах данные на
границе вычисляются из показанного точного решения. «Свои данные» позволяют
задать постоянные `f`, `g`/`r` и κ вручную. Запрашивать можно любой узел,
включая `(0,0)`, небольшой участок или всё поле.

```sh
python -m pdelab.boundary_cli run --left neumann --n 24 --point 0 12
python -m pdelab.boundary_cli run --left robin --kappas 2 0 0 0 --problem smooth
python -m pdelab.boundary_cli run --left neumann --right neumann --bottom neumann --top neumann
python -m pdelab.boundary_cli benchmark --left robin --n 24 --budgets 128 512 2048 --repeats 5
python -m pytest -q tests/test_boundary.py tests/test_boundary_solvers.py tests/test_boundary_interface.py
```

Экспорт: CSV, JSON с типами и массивами граничных данных, NPZ с полями и
автономный HTML. Серия измерений сравнивает отдельные запуски при разных
бюджетах и допусках; она не объявляет победителя при одинаковой точности.
Время включает построение граничного оператора и работу решателя, но не
JIT, эталон и графики. В UI есть ограничение объёма работы MC; CLI допускает
большие серии. Малый κ без Дирихле увеличивает длину путей и число итераций.

На `u*=1+x+2y+x²+y²` ошибка прямого решения находится на уровне округления.
На гладком косинусном примере тесты проверяют уменьшение ошибки примерно
в четыре раза при удвоении сетки для смешанных, полностью Robin и чистых
Neumann условий. MC проверяется по независимым seed относительно прямой
матрицы, в том числе для старта на границе и в углу с ненулевым потоком.
