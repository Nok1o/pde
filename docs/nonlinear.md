# Нелинейная теплопроводность: #12 и #13

Реализован MVP в единичном квадрате с Дирихле:

$$u_t=\nabla\cdot(k(u)\nabla u)+F,\qquad k(u)=1+\alpha u^2,\quad \alpha\ge0,\quad C=1.$$

Модель диффузии соответствует [нелинейной задаче FEniCSx](https://jsdokken.com/dolfinx-tutorial/v0.10/chapter2/nonlinpoisson_code.html).
Здесь используется собственная разностная схема и прогонки, а не FEM-код из учебника.
Основа — слитые #8 (`FrozenOperator`) и #10 (`HeatProblem`, сетка физического времени).
В PR также включена необходимая для #13 линейная MC-основа: один замороженный слой
и расчёт всех предыдущих полей без обращения к точному решению или ЛОМ.

## Запуск

`python main.py` → **Режим → Нелинейная теплопроводность**. По умолчанию:
α=0.5, n=8, Δt=0.01, T=0.1, одна точка в центре, четыре полных повтора MC.
Можно выбрать любой узел, включая границу. Внутри нелинейного алгоритма всё
равно вычисляется поле: оно нужно для проводимости следующей итерации и слоя.

```sh
python -m pdelab.nonlinear_cli run --n 8 --alpha .5 --T .1 --repeats 4
python -m pdelab.nonlinear_cli run --schedule linear --relaxation .7 --walks 128 --max-walks 2048
python -m pdelab.nonlinear_cli targets --n 8 --alpha .5 --repeats 16 --budgets 32 128 512
python -m pdelab.nonlinear_cli study --repeats 16 --seed 20261110
```

`run` сохраняет CSV, NPZ всех временных историй, JSON с причинами остановки и
автономные HTML: поле, ошибка, физическое время, нелинейная невязка. UI выдаёт
эти же файлы в ZIP. `targets` сохраняет таблицу 1/5/10% и доказательные данные
предварительных и контрольных серий. `study` запускает **фиксированный набор**
сеток, α, шагов и правил бюджета; параметры каждого случая находятся в CSV.
При несходимости `run` сохраняет диагностику и завершается с кодом 2.

## Дискретизация и три уровня итераций

1. **Физическое время**: обратный Эйлер; последний шаг укорачивается до T.
2. **Внешний Picard**: заморозить всё поле k(vʲ), решить линейную систему,
   применить релаксацию `vʲ⁺¹=(1−ω)vʲ+ωṽʲ⁺¹`, `0<ω≤1`.
3. **Внутреннее решение**: направленные прогонки или серия независимых путей MC.

На гранях сеточных ячеек применяется среднее
`kᵢⱼ=(k(vᵢ)+k(vⱼ))/2`, веса `wᵢⱼ=kᵢⱼ/h²`. Для одного слоя:

$$A(v^j)\widetilde v^{j+1}=b,\qquad
A(v)=\frac{I}{\Delta t}-\nabla_h\cdot k(v)\nabla_h,\qquad
b=\frac{u^m}{\Delta t}+F^{m+1}.$$

Проводимость не меняется между проходами или путями одной линейной серии.
Итерации не являются физическими шагами времени. Массивы индексируются `[y,x]`.

Внутренний решатель `solve_frozen_lod` использует **блочные итерации
Гаусса—Зейделя по строкам, затем по столбцам**. Каждый одномерный блок решается
прогонкой; остальные соседи входят в правую часть. В интерфейсе это обозначено
«Picard + ЛОМ». Это конкретный решатель направленными прогонками, а не перенос
постоянных коэффициентов старой тепловой схемы в нелинейную задачу.

Внутренняя невязка нормируется на норму правой части после исключения Дирихле.
Нулевая приведённая правая часть даёт нулевые внутренние неизвестные сразу.
Для внешней итерации используется исходное **нелинейное** уравнение:

$$R(v)=A(v)v-b,\quad
\rho=\frac{\|R(v)\|_\infty}{S},\quad
S=\max(\|b\|_\infty,\|A(v^0)v^0\|_\infty),$$
$$\eta=\frac{\|v^{j+1}-v^j\|_\infty}
{\max(\|v^{j+1}\|_\infty,\|v^j\|_\infty)}.$$

S фиксируется в начале слоя; нормы b и R берутся по внутренним узлам.
При нулевой нормировке отношение равно 0 только для нулевого числителя,
иначе бесконечности. Останов требует **обоих** допусков, поэтому случайно малое
изменение само по себе недостаточно. Счётчики и причины остановки для слоёв,
Picard и внутренних прогонок сохраняются отдельно. Несошедшийся слой
останавливает историю; его приближение можно исследовать, но оно не выдаётся
за решение при T. Средняя ошибка ансамбля не вычисляется по одним лишь удачным цепочкам.

## Независимый эталон

Сначала проверяется стационарная задача с тем же пространственным оператором,
затем один временной слой и полная история. `newton_system` независимо собирает
остаток по рёбрам и его аналитический Jacobian, не вызывая `FrozenOperator` или
Picard. Для ребра i–j вклад остатка равен

$$h^{-2}\left[1+\frac\alpha2(u_i^2+u_j^2)\right](u_i-u_j).$$

Его производные по uᵢ и uⱼ включают производную проводимости; простой
замороженной матрицы для Newton недостаточно. Прямое разреженное решение
поправки дополняется поиском длины шага, уменьшающим невязку. Эталон ограничен
n≤32. Нелинейный API допускает n≤64; сравнение в UI/CLI ограничено эталоном.
При α=0 поля совпадают с линейным временным решателем #10 до допуска решения.

Изготовленное решение:

$$u_*=1+e^{-t}\sin(\pi x)\sin(\pi y),\quad g=1,\quad u_0=u_*(0),$$
$$F=-(u_*-1)+2\pi^2(1+\alpha u_*^2)(u_*-1)-2\alpha u_*|\nabla u_*|^2.$$

Последний член необходим: `div(k∇u)=kΔu+k′|∇u|²`.
Аналитическое решение используется для ошибок, не для нелинейных итераций.

## MC замороженной системы и полной цепочки

При `dᵢ=1/Δt+Σwᵢⱼ` путь переходит к соседу с вероятностью `wᵢⱼ/dᵢ`,
добавляет `bᵢ/dᵢ` на посещении и завершается с вероятностью `(1/Δt)/dᵢ`
с нулевой дополнительной выплатой. На Дирихле выплачивается g нового слоя.
Значение предыдущего поля уже находится в b; повторная выплата его при
поглощении была бы двойным учётом. При стационарном слое σ=0 путь заканчивается
на Дирихле. Вероятности при переменной проводимости не равны 1/4.

Для уменьшения дисперсии Picard использует своё текущее поле v как контрольное:
`u=v+e`, `Ae=b−Av`, `e|∂Ω=0`. MC оценивает поправку e; коэффициенты A остаются
фиксированными на всю серию. Это не подстановка готового ответа ЛОМ.

Проверяются постоянный, линейно растущий и удваиваемый бюджеты с верхним пределом.
После прохождения двух критериев выполняется **новая независимая MC-серия**
на коэффициентах кандидата. Проверяются изменение и точная дискретная нелинейная
невязка её поля. Контрольная серия не используется для подгонки кандидата.
Её стоимость включена в метод. `max_steps` прекращает вызов без усечённой оценки;
счётчики включают уже проделанную работу. Общий лимит путей действует на всю историю.

Неопределённость оценивается повторами всей цепочки «время → Picard → MC».
SE последней линейной оценки не описывает эту неопределённость. Сохраняются
разброс результатов, RMSE отдельных запусков, среднее отклонение от Newton и
его исследовательский 95%-интервал по независимым цепочкам. Интервалы отдельных
случаев не скорректированы на множественные сравнения.

Измеряется также отклонение от детерминированного Picard при **таком же** внешнем
допуске и релаксации. Оно помогает отделить влияние выбранного допуска.
Для квадратичной проводимости

$$E[k(\widehat u)]-k(E[\widehat u])=\alpha\operatorname{Var}(\widehat u).$$

В CSV `conductivity_plugin_bias` оценивает эту величину для конечного поля в
выбранной точке. Это демонстрация механизма, а не доказательство причины всего
смещения решения: конечный допуск, перенос ошибки и адаптивный останов тоже
влияют на итог, в том числе при α=0. Условная несмещённость замороженного MC
не означает несмещённость всей нелинейной цепочки.

## Исследование и границы выводов

Разделение ошибок: пространственная — стационарный изготовленный пример;
временная — сравнение с независимым интегрированием полудискретной системы Radau;
нелинейная — Picard против Newton на одинаковых h и Δt. Численные результаты и
фиксированный набор для повторения находятся в [отчёте](nonlinear-study.md).

В таблице 1/5/10% бюджет выбирается по предварительным цепочкам, затем проверяется
на независимых seed. При провале контрольной серии время пустое, повторного
подбора по этим данным нет. Сравнивается RMSE отдельных результатов, не ошибка
их среднего. Время ЛОМ усредняется по указанному числу повторов; допуск ЛОМ
задаёт пользователь, его оптимальность не утверждается. Начальный N исследования
не может превышать выбранный `max_walks`.

Полное время включает все слои, замораживания, прогонки, пути, контроль и хранение
истории. JIT, Newton-эталон и рисунки исключены. `workspace_bytes` — резерв плотных
массивов, временной копии истории и Python-записей итераций, не измеренный RSS;
JIT, графики и sparse LU туда не входят. История ограничена 16 млн значений,
сравнение всех повторов — 8 млн; UI ограничивает каждую MC-цепочку 2 млн путей.

MVP не включает 3D, Нейман/Робин, нелинейную теплоёмкость и реакцию. Линейный
временной MC проверен здесь как основа #13; отдельный интерфейс общего #11
остаётся самостоятельной задачей. На текущем алгоритме запрос одной точки
не устраняет подготовку остальных узлов — именно это сравнивается по стоимости.
