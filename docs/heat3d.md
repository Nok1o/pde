# Квазилинейная теплопроводность в 3D — issue #25

Режим решает в единичном кубе задачу

$$u_t=\operatorname{div}((1+\alpha u^2)\nabla u)+F(x,y,z,t),\qquad \alpha\geq0.$$

Теплоёмкость равна 1. На всех шести гранях заданы **условия 1 рода**,
начальное поле известно. Доступны два изготовленных примера: синус и полином
с перекрёстными членами. Их формулы, источник и общий интерфейс находятся в
[контракте](heat3d-contract.md). Программа сравнивает вычисленное решение с
аналитическим в выбранной точке, участке, срезе или внутреннем поле.

## Запуск

`python main.py` → **Квазилинейная теплопроводность** → **3D**.
Настройте сетку, физическое время и область запроса, затем нажмите
**Рассчитать 3D**. Исследование 1/5/10% запускается отдельной кнопкой на своей
вкладке. Изменение параметров и просмотр графиков сами вычисления не запускают;
выгрузка всегда относится к параметрам выполненного расчёта.

Для воспроизводимого запуска без интерфейса:

```sh
python -m pdelab.heat3d_cli run --n 8 --alpha .5 --dt .01 --T .02 --newton --out runs/heat3d-run
python -m pdelab.heat3d_cli run --case polynomial --n 8 --query slice --plane yz --index 3 --out runs/heat3d-slice
python -m pdelab.heat3d_cli study --n 8 --dt .01 --T .02 --repeats 5 --seed 42 --out runs/heat3d-study
```

`--point X Y Z` задаёт индексы узла, включая границу. `n` — число интервалов
по каждой оси; число узлов равно `(n+1)^3`. Публичные координаты — `(x,y,z)`,
массивы и экспортируемые списки точек — `[z,y,x]`. `--help` показывает допуски,
релаксацию, ограничения и параметры исследования. Предусмотрено `n≤64`;
независимый Ньютон ограничен `n≤16`.

## Как идёт расчёт

1. На каждом физическом слое используется неявный Эйлер. Последний шаг
   укорачивается до заданного `T`; при `T=0` возвращается начальное поле.
2. Пикар начинает с **вычисленного** предыдущего слоя, обновив данные границ.
   Проводимость замораживается по текущему приближению на всё линейное решение.
3. Общий семиточечный оператор использует арифметическое среднее проводимостей
   соседних узлов. Известные граничные значения переносятся в правую часть.
4. Линейная система решается повторными прогонками по целым линиям: x, затем y,
   затем z. В каждой прогонке сохранена полная диагональ системы, а поперечные
   соседи входят в правую часть с последними доступными значениями. Это линейная
   итерация Гаусса — Зейделя по направлениям внутри Пикара, а не три физических
   шага времени. Здесь нет матричной блочной прогонки из #26.
5. После релаксации пересчитываются проводимость и **нелинейная** невязка.
   Слой принимается только при выполнении обоих относительных допусков:

$$\frac{\|A(u)u-b(u)\|_\infty}{S}\leq\varepsilon_R,\qquad
\frac{\|u_{new}-u_{old}\|_\infty}{\max(\|u_{new}\|_\infty,\|u_{old}\|_\infty)}
\leq\varepsilon_u.$$

Масштаб `S` фиксируется в начале слоя как максимум норм правой части и
применённого оператора по свободным узлам. Линейный критерий —
`||Au−b||∞/||b||∞` по тем же узлам. При нулевом знаменателе отношение равно
нулю только для нулевого числителя, иначе бесконечности. Точное решение
не подставляется вместо неизвестных полей и коэффициентов.

Независимый Ньютон сам собирает нелинейную невязку и её якобиан, решает малую
разреженную систему и уменьшает шаг при необходимости. Это диагностика той же
разностной задачи, а не конкурент в таблице времени достижения аналитической
точности. Его критерий — относительная нелинейная невязка; отличие от Пикара
в критерии остановки не скрывается.

## Что означает таблица 1/5/10%

Для каждого полного запуска вычисляется относительная ошибка в области Q:

$$e_r=100\frac{\|u_r-u^*\|_{2,Q}}{\|u^*\|_{2,Q}},\qquad
\bar e=\frac1R\sum_{r=1}^{R}e_r.$$

В одной точке это обычная абсолютная относительная ошибка. Для нескольких
точек это относительная L2-норма. Метрика имеет ID `mean_run_relative_l2_v1`;
старые результаты с другой метрикой не переименовываются. При нулевом эталоне
процентная цель неприменима, сохраняется абсолютная L2-ошибка.

Сетка, шаг времени и область Q фиксированы. Подбирается допуск Пикара из
заданного списка, по умолчанию `1e-3, 1e-5, 1e-7, 1e-9`. Предварительная серия
должна достичь фиксированной доли цели, по умолчанию 0.8. После выбора всех
кандидатов проводится новая финальная серия; её неудача **не запускает повторный
подбор**. Одинаковый выбранный кандидат может обслуживать несколько целей.
Только полностью завершённая финальная серия с нужной средней ошибкой получает
статус «Достигнута» и среднее время. Для детерминированного ЛОМ повторы нужны
для измерения времени: новые seed не меняют его решение.

Если ошибка сетки и времени уже велика, ужесточение допуска Пикара не обязано
помочь. Неподтверждённые цели сохраняют причину, достигнутую ошибку и затраты.
Это минимальная часть инфраструктуры #31 для нового режима; перенос старых
режимов и итоговые сравнительные исследования остаются отдельной задачей.

## Время, память и выгрузки

Каждый запуск оплачивает подготовку полей, коэффициентов, все физические слои,
линейные и внешние итерации, диагностику остановки. Прогрев JIT, эталоны и
отрисовка исключены. `preparation_seconds` уже входит в `seconds`.
Даже запрос одной точки требует решения полных полей. Предыдущее и текущее
поле хранятся полностью, все прошлые поля не накапливаются.

`workspace_bytes` — оценка численных буферов и диагностической истории,
а не измеренный пик памяти процесса. `peak_rss_bytes=null` означает, что такой
пик не измерялся. Оценка включает подготовку начального поля и сетку времени
до их выделения; рост истории проверяется внутри внешних итераций.
Лимит времени мягкий: проверяется между завершёнными внешними
итерациями и физическими слоями. Начатое линейное решение может выйти за него.

При отказе значения в целевой момент не выдаются. Экспорт содержит причину,
`completed_until`, число принятых слоёв и фактические итерации, включая работу
в неудачном слое. CLI сначала сохраняет результат, затем возвращает код 2 при
неудаче запрошенного расчёта, проверки Ньютоном или исследования.

Последнее приближение неудачного слоя хранится отдельно в `diagnostic_field`
с `diagnostic_time`. В NPZ сравнения это `failed_candidate` (для Ньютона —
`newton_failed_candidate`), полный массив `[z,y,x]`; поле `values` остаётся пустым.
Если слой ещё не удалось подготовить, кандидата нет. В исследовании сохраняются
скалярные диагностики всех попыток без накопления полей каждого запуска.

JSON/CSV/ZIP содержат параметры, версии, commit, признак локальных изменений,
область Q, метрику, историю и отдельные предварительные/финальные запуски.
NPZ сохраняет значения в том же порядке точек. `reproduce.txt` содержит команду
повторения. Полные поля прошлых временных слоёв в экспорт не включаются.
Повторная выгрузка в ту же папку удаляет устаревшие служебные файлы предыдущего
запуска; посторонние файлы не затрагиваются.

## Проверки и границы готовности

Тесты отдельно проверяют направление прогонок, матрицу и исключение границ,
якобиан численными производными, совпадение Пикара с независимым Ньютоном,
линейный предел и укороченный шаг. Уточнение только времени показывает первый
порядок; уточнение только пространства — второй на гладком примере. Проверяются
отказы, отсутствие подстановки эталона, протокол финальных серий, CLI и переход
в новый режим из основного приложения.

В этом режиме ещё нет MC/контрольного приближения (#28), условий 3 рода (#27)
и матричной прогонки (#26). Они требуют подключения к общему оператору.
Результаты старых стационарных и двумерных методов не выдаются за новые
3D-временные алгоритмы. Этот этап подтверждает корректность базового решателя,
но сам по себе не устанавливает выигрыша по скорости.
